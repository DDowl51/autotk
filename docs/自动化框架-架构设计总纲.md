## 0. 一页纸

**做什么**:一个**可复用的移动端自动化框架**(core),外挂**按 app 的插件**(首个 = TikTok)。core 是「截图→VLM 定位→闭环决策→驱动执行」的引擎 + 多设备编排,**完全不认识 TikTok**;TikTok 的一切(认什么、做什么、业务概率)都在 `plugin-tiktok` 里。

**为什么这样**:①第一性——屏幕即真相、动作是盲的、环境对抗、识别稀缺(§1);②可复用——以后做别的 iOS app 自动化,加个插件即可,不碰 core(开闭原则,§2)。

**首个插件(TikTok)交付 5 个功能**:①关键词搜索互动 ②主页视频互动 **+ 给评论者私信**(同一趟)③关注监控打粉 ④发布视频 ⑤评论区下滑看更多。**不做**推荐页养号。

**规模(2026-07-10 实测下调)**:批处理不支持(模型 only batch=1),单卡吞吐≈单流。**VLM 唯一指令源模式:单卡 ~10 台(裸)→ ~35–50 台(FP8+一卡多实例);混合兜底 ~150–200**。几百台 = 多卡分片。详见性能报告 §7.0。

## 1. 第一性原理(公理)

- **A1 屏幕即唯一真相**。读不到元素树(`snapshotMaxDepth:1`),唯一可靠信息 = 截图像素 + 操作历史。
- **A2 动作是盲的**。tap/swipe 无返回值,效果只能下一帧截图观测。
- **A3 环境对抗且非确定**。随时插广告/弹窗/权限窗/直播/内嵌页;网络使转换时间不定。
- **A4 识别稀缺**。像素≈免费、OCR 便宜、VLM 精准但贵(~0.5s)且是吞吐瓶颈。
- **A5(新)复用优先**。跨 app 不变的能力必须与某个具体 app 解耦,否则每做一个 app 重造一遍。

## 2. 架构基调:core + plugin + 依赖倒置

**不变(core / 框架)** vs **每 app 变(plugin)**,分得很干净:

| 层面 | 不变 → core | 每 app 变 → plugin |
|---|---|---|
| 设备操作 | 截图/点/滑/输入(Driver **接口**) | —(iOS 都一样,driver 是平台实现,非 plugin) |
| 感知 | grounding + OCR(Perceptor **接口**) | 认什么(Target 短语)= plugin 数据 |
| 控制 | Step 合同 + 观测-决策-执行-验证闭环 + await | —(算法与 app 无关) |
| 编排 | 多设备并发/调度/健康自愈/拟人化 | — |
| 业务 | — | 动作库(搜索/主页/私信/…)、工作流、概率参数 |

**依赖倒置**:core 定义接口(`Driver`/`Perceptor`/`Plugin`/`StateStore`),平台/插件实现之。**core 不 import 任何插件**;`master` 运行时装配:`runFleet({ driver, perceptor, plugin })`。

**开闭**:加新 app = 新 `plugin-xxx` 包(不动 core);加新功能 = 插件里新动作模块(不改老模块)。

    human/       chance/jitter

  perceptor-vlm/      ★Perceptor 实现:调 services/perception 的客户端
  plugin-tiktok/      ★TikTok 插件:targets + 动作库 + 工作流 + 参数 schema(依赖 core)
  shared/ telemetry-sdk/ license-sdk/   复用
services/
  master/             ★运行时:装配 core+driver+perceptor+plugin,连 Hub,跑编排

## 4. 核心接口(架构的接缝,依赖倒置)

```ts
// —— 设备驱动(L0)。iOS-WDA 实现;会话/自愈/超时在实现内部 ——
interface Driver {
  screenshot(): Promise<Buffer>;               // PNG
  tap(p: Point): Promise<void>;
  swipe(from: Point, to: Point, durMs: number): Promise<void>;
  typeText(s: string): Promise<void>;
  activateApp(appId: string): Promise<void>;   // 动作前置(前台守卫)
  ensureHealthy(): Promise<void>;              // 会话失效自愈(WDA 404 → 重建)
}

// —— 感知。LocateAnything+OCR 实现。locate=坐标唯一源,readText=只读文本 ——
interface Perceptor {
  locate(img: Buffer, queries: LocateQuery[]): Promise<Hit[]>;   // 组合查询,缺席不返回
  readText(img: Buffer, region?: Box): Promise<TextLine[]>;
}
type LocateQuery = { id: string; phrase: string; region?: Box };
type Hit = { id: string; box: Box; score: number };

// —— 插件:一个 app 提供给 core 的全部 ——
interface Plugin {
  id: string;                       // "tiktok"
  appId: string;                    // driver.activateApp 用,如 bundleId
  targets: Target[];                // 声明式感知(见 specs/target-registry)
  workflows: Record<string, Workflow>;  // 任务名 → 工作流
  params: ParamsSpec;               // 参数结构 + 校验 + 默认(见 specs/L3-业务规格)
}

// —— 跨天状态(去重/限量;DM 名单、每日计数)——
interface StateStore {
  has(ns: string, key: string): Promise<boolean>;
  add(ns: string, key: string): Promise<void>;
  incrDaily(ns: string, key: string): Promise<number>;   // 按「账号+日期」计数
}

// —— 工作流 = 一串 Step(声明式,用 core 的 L1 基本操作)——
type Workflow = (ctx: RunContext) => Promise<void>;  // 内部用 ctx.step(...) / ctx.chance / ctx.jitter
```

core 另提供给工作流的 `RunContext`:`step(contract)`(跑一步决策)、`locate/readText`(经 Perceptor)、`tapTarget/awaitTarget/swipeNext/typeInto`(L1)、`chance/jitter`(拟人)、`state`(StateStore)、`params`、`shouldStop/withinWindow`、`log/onEvent`。

## 5. 四层模型 → 落到 core / plugin

```
L3 工作流   plugin  search / profileAndDM / followMonitor / publish   (业务编排+概率)
L2 动作     plugin  openComments/likeVideo/dmCommenter/scrollComments (app 特定,用 L1+Targets)
L1 基本操作 core    tapTarget/awaitTarget/swipeNext/typeInto/readText/handleHazards
L0 原子     core接口+driver实现  tap/swipe/typeText/screenshot/activateApp
```
- L0/L1/引擎/编排在 **core**;L2 动作 + L3 工作流 + Targets + 参数在 **plugin**。
- `swipeNext` 盲滑(总纲原则):固定手势不问 VLM,但前置该 Step 的 hazards 检测(确认无浮层才滑)。

## 6. Step 合同与决策(core,与 app 无关)

```ts
interface Step {
  intent: string;
  act?: BasicOp;          // 本步动作(缺省=纯观察)
  expected: string[];     // 期望 TargetId
  hazards: string[];      // 危险 TargetId(global ∪ 页面专属,来自插件 Target)
  verify: string[];       // 成功判据(通常=下一步 expected)
  timeout: number;
  onFail: Escalation;     // retry→variants→recover→alertOperator(终点永远告警不盲动)
}
```
决策函数(每步):截图 → `Perceptor.locate([hazards∪expected])` 一次组合查询 → **危险优先**(系统级>遮挡级>分类级)处理后重观测 → 期望在则执行 act + `await(verify)` → 期望不在先当加载中轮询 → 超时才升级。(公理 A1–A4 的直接落地。)

## 7. TikTok 插件:5 个工作流

### 7.1 关键词搜索互动 `search`
`pick(searchKeywords)` → 点搜索→输入→提交→**点第二个结果**(跳广告位)→ 遍历 `randInt(3,8)` 条 → 每条 `interactWithVideo`(点赞/收藏/关注/进评论区赞+回,按 kwSearch 概率)→ back → 结束 returnToFeed。(语义见 L3 §6.2。)

### 7.2 主页互动 + 私信 `profileAndDM`(🆕 合并)
进**我自己**主页 → `min(作品数, maxVideoCount)` 条,每条进评论区:
```
scrollComments 收集评论(可下滑多屏,§7.5)
for 每条评论:
  # 常规评论互动
  chance(commentLikeProb) → likeComment
  matched = matchComment(text, commentMatchKeywords)
  chance(commentReplyProb) 且(无关键词表 或 matched)→ 生成话术 → 回复(postReplies 真才发)
  # 🆕 私信(命中 DM 关键词 且 未私信过 且 未超每日上限)
  if matchComment(text, dmKeywords) 且 !state.has("dm:"+account, username) 且 dailyDM < dmDailyCap:
      dmCommenter(comment)   # §7.4
```
点赞/回复/私信各带 `jitter(clickWaitTime)` 拟人停顿。

### 7.3 关注监控打粉 `followMonitor`
`following.moduleEnable` 开启=纯打粉、与其它互斥。切「关注」流(点 `nav.following-tab`)→ 遍历 `randInt(3,8)` 条 → **到底检测**(连续两条 caption 相同=滑不动)→ 直播卡盲滑跳过 → 进评论区**命中关键词优先回复**(interactProb=1、commentReplyProb=0.8)→ 结束切回 `nav.foryou-tab`。**暂不发私信**(维持评论回复打粉)。

### 7.4 私信动作 `dmCommenter`(🆕,平台风险最高)
```
tapTarget(评论者头像/名) → awaitTarget(对方主页) 
→ locate(profile.message-button):不存在 = 对方隐私不可私信 → 跳过(记 state 防反复试)
→ tapTarget(私信按钮) → awaitTarget(dm.input) → typeInto(私信话术) → tapTarget(dm.send)
→ state.add("dm:"+account, username);state.incrDaily("dm-count", account)
→ 返回我的主页视频(back)
```
- **话术**:独立的 DM 模板列表(复用「固定模板+占位符」机制,{user}/{kw})。
- **去重**:按 username 跨天(StateStore,Postgres 表)。
- **限量**:每账号每日上限(默认 **20**,可配)。到顶停发。
- ⚠️ **能不能发要真机先验**(私信按钮有无 + TikTok 反垃圾)——G2 首验项。

### 7.5 评论区下滑 `scrollComments`(🆕 基本能力,多工作流复用)
```
seen = Set(); dry = 0
loop:
  readText(评论区) → 解析成评论 → 加入 seen(按 author+text 去重)
  if 本轮无新评论: dry++; if dry>=2 break     # 到底(连续两屏无新)
  else dry=0
  面板内向上滑一屏(纯竖直,不误触)
  上限 maxScrolls 兜底
```

### 7.6 发布 `publish`(复用老语义)
Hub 文件夹工作流下发(视频源 + 文案)→ 复位到能看到底部 [+] 的基地 → +→上传→选相册最新→下一步→文案→发布。锚点全改 VLM phrase(无需标定)。

## 8. 运行时与编排(core,services/master)

- 每台手机一个 `PhoneSession`{ udid, driver, session游标, seen/hazardLog, health, params }。
- 主控循环:观测→`decide`→执行→验证(§6);VLM 调用汇入 GPU 批(services/perception §协议规格)。
- **调度**:分时段窗口(taskWindows)+ 模块互斥优先级(following 开=纯打粉;否则 profileAndDM 每日一次;否则 search)+ batchGen 超时隔离 + 退避熔断(语义见 L3 §3)。**无 For You 后**,活跃度靠这些任务本身。
- 冲突裁决:PhoneSession 与截图冲突时**以截图为准**(A1)。
- 自愈:WDA 掉线 `driver.ensureHealthy()`;同一危险 N 次关不掉 → alertOperator。

## 9. 感知与协议(见 specs/协议规格)

- master↔perception:`/perceive`(组合查询,每步 1 次)+ `/ocr`;图像 master 侧下采样(512/640)+ JPEG;服务端批处理。
- master↔Hub:复用现有 socket.io 协议(`ConfigPatch` 已含全部业务参数,含 `following`);D3 平铺 vs 聚合。
- **参数下发**:`ParamsSpec` 字段与 `packages/shared` `ConfigPatch` 对齐;需加 **DM 相关字段**(dmKeywords/dmTemplates/dmDailyCap/dmEnable)——`shared` 扩展登记同步纪律。

## 10. 状态与持久化(🆕)

DM 去重/限量需要**跨进程重启的持久状态**(内存不够):
- core 出 `StateStore` 接口;实现 = **Postgres 表**(复用现有 pg 基础设施)。
- 表:`dm_sent(account, username, sent_at)`(去重)+ 每日计数(`account+date` key)。
- 其余状态(养号统计/游标)仍内存 + 定期上报 Hub(A1:屏幕是真相,状态只是索引)。
