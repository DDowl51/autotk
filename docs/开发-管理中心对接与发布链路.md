## W1 · master↔Hub 客户端(flat,D3=A)

**位置**:`services/master/src/hub/`　**依赖**:`socket.io-client`、`@mc/shared`(EVT/消息类型)。

### 文件与职责
| 文件 | 职责 |
|---|---|
| `hubClient.ts` | 连 Hub;每台手机一个逻辑设备(deviceId=UDID);`device:register` 注册;断线自动重连;路由 `config:apply`/`publish:task` 到回调;发 `device:status`/`device:log`/`config:result`/`publish:result` |
| `statusReporter.ts` | 把 `PhoneHandle`(orchestrator)映射成 `DeviceStatus`(running/module/page/stats/alert/battery),定时上报 |
| `configInbox.ts` | 收 `ConfigPatch` → 校验 → `PhoneHandle.updateParams`;回 `config:result{ok/error}` |

### 关键接口(为测试锚定签名)
```ts
// hubClient.ts —— 一个 master 进程连一次 Hub,代理 N 台
export interface HubClientDeps {
  hubUrl: string;
  socketFactory?: (url: string) => MinimalSocket; // 测试注入假 socket
  onConfigApply(deviceId: string, patch: ConfigPatch): Promise<{ ok: boolean; error?: string }>;
  onPublishTask(deviceId: string, task: PublishTaskMsg): void;
  log?(msg: string): void;
}
export interface HubClient {
  registerDevice(info: DeviceRegisterMsg): void;      // 每台上线时注册
  reportStatus(deviceId: string, s: DeviceStatus): void;
  reportLog(deviceId: string, lines: DeviceLogMsg[]): void;
  reportPublishResult(deviceId: string, taskId: string, status: PublishStatus, error?: string): void;
  close(): Promise<void>;
}
export function createHubClient(d: HubClientDeps): HubClient;

// statusReporter.ts
export function toDeviceStatus(h: PhoneHandle, extra: { battery?: DeviceBattery; page?: string }): DeviceStatus;
```
`MinimalSocket` = `{ on; emit; connect; disconnect; connected }` 的最小接口 → 测试注入内存假 socket,不起真网络。

### 装配(run.ts)
- master 起 Fleet 后:对每台 `fleet.add` 的手机 `hub.registerDevice`;
- 定时(如 5s)`toDeviceStatus(handle,…)` → `hub.reportStatus`;
- `onConfigApply` → `handle.updateParams`(校验失败回 error 不生效);
- `onPublishTask` → 交给 W3 编排(先占位)。

### 测试点(W1)
- 注册:N 台各发一次 `device:register`,deviceId 唯一。
- 状态映射:PhoneHandle(module/stats/alert)→ DeviceStatus 字段正确;含新 `dmFailed`。
- config 路由:`config:apply{jobId,patch}` → 调 onConfigApply → 回 `config:result{ok}`;校验失败回 `{ok:false,error}`。
- publish 路由:`publish:task` → 调 onPublishTask(不实际发布,W1 仅路由)。
- 断线重连:socket disconnect → reconnect 后重新 register。
- 全用假 socket,离线确定性。

## W2a · master 侧收视频通道(β1)

**位置**:`services/master/src/receiver/`　**依赖**:`socket.io`(server)。

master 跑一个**小 socket 服务**,供各手机收视频端(β1 后台常驻)连入。

### 文件与职责
| 文件 | 职责 |
|---|---|
| `receiverServer.ts` | socket.io server;收 `receiver:hello{udid}` 记录连接;`pushDownload(udid,cmd)` 下发下载命令;收 `receiver:progress` 转给编排 |
| `receiverRegistry.ts` | udid → 连接/在线态/最近一次下载进度;掉线标记 |
| `protocol.ts` | master↔收视频端 内部协议(复用 publish 语义,**非 Hub 协议**) |

### 内部协议(master ↔ 收视频端)
```ts
// 收视频端 → master
type ReceiverHello    = { type: "hello"; udid: string };
type ReceiverProgress = { type: "progress"; taskId: string; status: "downloading"|"downloaded"|"failed"; assetId?: string; error?: string };
// master → 收视频端
type DownloadCommand  = { type: "download"; taskId: string; url: string; videoName: string };
```

### 关键接口
```ts
export interface ReceiverHub {
  onProgress(cb: (udid: string, p: ReceiverProgress) => void): void;
  isOnline(udid: string): boolean;
  pushDownload(udid: string, cmd: DownloadCommand): Promise<void>; // 端不在线 → 抛错
  close(): Promise<void>;
}
export function createReceiverHub(opts: { port: number; log?(m:string):void }): ReceiverHub;
```

### 测试点(W2a)
- hello 注册 → isOnline(udid) 真;掉线 → 假。
- pushDownload:在线正常下发;不在线抛错。
- progress 回调透传(downloading/downloaded+assetId/failed+error)。
- 用假 socket server / 内存 socket 对测,不起真端口(或起随机端口本地自连)。

## W3 · master 发布编排

**位置**:`services/master/src/publish/orchestrator.ts`　**依赖**:W2a(ReceiverHub)、orchestrator(PhoneHandle.runExclusive)、plugin-tiktok(`publish`)。

### 流程(状态机,对齐 `PublishStatus`)
```
收 publish:task(deviceId,url,caption,videoName)
  → receiverHub.isOnline? 否 → 回 failed(收视频端离线)
  → pushDownload → 等 progress: downloaded(assetId) | failed(超时也算 failed)
  → 成功:handle.runExclusive("publish", ctx => publish(ctx, {caption}, pageHazards("publish"), pageHazards("feed")))
  → 回报 publish:result(published/failed)
```
- **串行时序(D-γ)**:确认相册已存(收到 downloaded)**才**切 TikTok 发布;runExclusive 保证不抢前台。
- 下载超时/发布失败 → failed,Hub 可重派。

### 关键接口
```ts
export interface PublishOrchestratorDeps {
  receiver: ReceiverHub;
  getHandle(deviceId: string): PhoneHandle | undefined;   // udid→PhoneHandle
  publishFn(ctx: RunContext, input: { caption: string }): Promise<PublishResult>; // = plugin.publish 包装
  report(deviceId: string, taskId: string, status: PublishStatus, error?: string): void; // → hub.reportPublishResult
  downloadTimeoutMs?: number;
  now(): number; sleep(ms:number): Promise<void>;
}
export function handlePublishTask(deviceId: string, task: PublishTaskMsg, d: PublishOrchestratorDeps): Promise<void>;
```

### 测试点(W3)
- 端离线 → 直接 failed,不发布。
- 下载 failed → 不进发布,回 failed。
- 下载 downloaded → runExclusive 被调、publishFn 被调、published 回报。
- 发布 failed → 回 failed。
- 下载超时 → failed。
- 全 mock(receiver/handle/publishFn),离线确定性。

## W2b · 收视频端 App(Mac-build)

**位置**:`apps/receiver/`(**新起干净包**,RN/Expo,像 apps/mobile 一样在 root workspace 之外自带安装)。
**理由**:旧 autotk 已退役且带引擎杂物,新起一个只含"收→下载→存相册"的极小 App 更干净;**抢救**其 3 个纯逻辑文件。

### 组成
| 来源 | 内容 |
|---|---|
| 抢救 `apps/mobile/src/publish/downloader.ts` + `album.ts` + `publishQueue.ts` | 下载编排 + 存相册 + 队列/状态机(去掉 `publishVideo` 步,止于 downloaded) |
| 新写 | socket 客户端(连 **master**,发 hello、收 download、回 progress)+ 极小状态 UI(大字显示 待命/下载中/已存相册/失败——供真机肉眼与 VLM 读)+ 保活(location) |
| `app.json`(照 apps/mobile) | expo-media-library + expo-location(Always+UIBackgroundModes)+ NSLocalNetworking |

### 配置
- 端装机时配:自己的 `udid`(= Hub/编号)+ `master 地址`(socket URL)。可复用 apps/mobile 的 env 机制(`EXPO_PUBLIC_*`)。
- 权限授予(装机一次性):相册"全部照片"、定位"始终"。

### 测试点(W2b)
- 纯逻辑(可在包内 node --test,像 apps/mobile):队列去重/FIFO(复用旧 `publishQueue.test`)、下载超时→failed、progress 回报映射。
- 真机(Mac 构建后):真下载存相册、后台保活维持 master 连接、断连重连。
