# 管理中心 改进需求文档（R1）

针对桌面端阶段 1 看板的 4 条改进意见。涉及三端：**Electron 桌面端**、**Hub**、**autotk 手机端**。

---

## 改进 1：界面更专业

**现状**：已是「控制室暗色」风格 + 6 页导航，但信息偏静态、缺运维看板该有的密度与交互。

**需求**：往「专业运维监控台」靠：

- **搜索 / 筛选 / 排序**：设备按名搜索；按状态（在线/运行/告警/离线）筛选；列可排序。
- **告警中心**：独立告警列表，带级别、时间、设备，可确认（ack）/历史。
- **数据可视化**：机群在线趋势、互动量趋势（小图）；单机 mini sparkline（可选）。
- **设备详情升级**：详情里带「实时日志尾巴」（见改进 2）、状态时间线。
- **状态语义更细**：在线空闲 / 运行中 / **疑似卡住**（在线但 X 分钟无进展）/ 告警 / 离线；陈旧数据标记（last-update 过久）。
- **批量选择**：表格多选（为阶段 2 批量设置铺路）。

**验收**：能搜/筛/排；告警可一眼定位并确认；状态语义准确；界面密度与专业度对标常见监控台（Grafana 类）。

**涉及端**：桌面端为主；「疑似卡住」「陈旧」判断需要手机心跳/进度时间戳（Hub/手机轻量配合）。

---

## 改进 2：控制中心看手机日志

**现状**：看板只有聚合状态，看不到手机端运行日志（哪条视频、点了什么、为什么卡）。

**需求**：

- 手机端把运行日志（带级别 info/warn/error + 时间）**实时上报 Hub**。
- Hub 为每台设备保留**最近 N 条**日志（环形缓冲），并把新日志**推流**给正在查看该设备的操作员。
- 桌面端：设备详情里有「日志」面板，实时滚动；可暂停/搜索/按级别过滤；可选「全局日志流」聚合多台。

**验收**：手机在跑时，控制中心能近实时看到该机日志；断线重连后能补看最近 N 条；不卡顿（限流/截断）。

**涉及端**：**三端都改**。强依赖「autotk↔Hub 接入」（手机端目前还没连 Hub）。

---

## 改进 3：模块列显示中文

**现状**：设备页「模块」列显示 `forYou` / `kwSearch` / `persHome`（代码名）。

**需求**：映射成中文 —— `forYou`→**推荐页**、`kwSearch`→**关键词搜索**、`persHome`→**个人主页**；未知值原样显示。

**验收**：模块列、详情里的「当前模块」都显示中文。

**涉及端**：**仅桌面端**（纯映射，最快）。

---

## 改进 4：设备详情显示「当前页面」

**现状**：详情抽屉有「当前页面」字段但为空——因为手机端没上报 `page`。

**需求**：手机端在状态里上报**当前页面**（如 推荐流 / 评论区 / 搜索结果 / 个人主页 等），桌面端详情显示（中文）。

**验收**：手机在不同页面时，详情「当前页面」实时更新为对应中文。

**涉及端**：**手机端 + 桌面端**。手机端把页面状态喂进上报；依赖「autotk↔Hub 接入」。

---

## 依赖与建议顺序

```
改进 3（中文映射，桌面端，最快）           ← 立即可做，无依赖
改进 1（界面更专业，桌面端为主）           ← 可与 3 并行
─────────────────────────────────────
前置：autotk ↔ Hub 接入（手机端连 Hub、上报状态/日志/页面）
改进 4（当前页面，手机+桌面）             ← 依赖前置
改进 2（手机日志，三端）                  ← 依赖前置，最重
```

- 改进 3、1 是桌面端独立项，先做、见效快。
- 改进 2、4 都卡在**手机端还没接 Hub**——这正是之前说的"嵌入手机 app"那步，要先做接入，再做日志/页面上报。

- 日志保留条数 N（每台）、是否落库（持久）还是仅内存环形缓冲？建议先内存（如 500 条/台）。
  A：内存
- 「疑似卡住」判定阈值（无进展多少分钟）？建议默认 5 分钟，可配。
  A： 默认5分钟， 可配置， 放到设置页面
- 日志量大时的限流策略（手机端合并/采样上报）？
  A：你来想办法
- 设备名/别名从哪来（iOS 设备名 vs autotk 内设别名）？影响详情与文件夹命名（与 #1 阶段 3 一致）。
  A：你来想办法， 最好兼顾可读性+唯一性
