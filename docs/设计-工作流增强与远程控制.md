## 关键设计

### 4 · recoverToFeed 多策略(核心)
现状只会"边缘右滑退 pushed 页",**关不掉评论面板**(浮层,竖直下滑才关)——养号工作流最常停这。改为每轮探测后按情况选手势:
1. **危险弹窗** → 探测步 hazards 已自动处理(现有)。
2. **评论面板在场**(locate `comments.panel`)→ **竖直下滑关**(y0.35→0.96)。← 补缺口
3. **其它**(pushed 页)→ **边缘右滑退**一级。
`maxSteps` 3→**6**(私信页深链);兜底仍 `alertOperator`(绝不盲动,坑清单 D1)。
另:`publish.ts` 开头补 `recoverToFeed`(现在"假定已在可发起页")。

**衔接契约**:所有工作流都从**推荐流**起步(search 点放大镜/follow 点关注 Tab/profile 点"我"Tab 都需底部导航)。recoverToFeed 在每批工作流前跑,把任意深页带回推荐流 → 下一个从干净基地开始。

### 2 · 文案命中 gate 关注(复用 pos/neg,无协议改动)
```
captionAllowsFollow(caption, pos, neg):
  if neg 非空 且 matchComment(caption, neg) → false      // 命中排除词不关注
  if pos 空 或 含 "*" → true                              // match-all(默认 ["*"] → 纯概率,向后兼容)
  return matchComment(caption, pos) !== null             // 命中正词才关注
```
仅在需要 gate 时(pos 有真词 或 neg 非空)才读文案 OCR,省调用。`interactWithVideo` 加 `opts.canFollow?:boolean`(默认 true,不影响其它调用方)。

### 5 · activeWorkflow
- `TikTokParams` + `ConfigPatch` 加 `activeWorkflow?: "search"|"followMonitor"|"profileAndDM"|"off"`。
- `pickWorkflow` 改:显式设了就返回它(前提满足,如 search 需 searchKeywords);缺省回落原 moduleEnable 优先级(向后兼容)。
- ConfigPatch 加字段 → 同步 gateway;desktop 下拉框(Mac/Electron,后做)。

### 6 · 远程启停(pause/resume)
- **core**:`PhoneHandle` 加 `pause()`/`resume()` + `isPaused()`;主循环开头 `if (paused) idle`(像不在时段窗);恢复后下批先 recover 再跑。
- **shared**:新事件 `device:control` + `{action:"pause"|"resume"}`(手机方向:Hub→device)+ 结果沿用 status。
- **master**:hubClient 路由 `device:control` → `handle.pause()/resume()`;上报 `DeviceStatus.running` 反映。
- **desktop**:每台一个启停按钮(后做,Electron)。
> "停止"=挂起停在原地(不移出 Fleet);"开始"=恢复→下批 recover→跑。立即停用它(最近检查点)。

## 测试点(先写)
- **recover**:已在基地→true 不动;评论面板→下滑关→回基地 true;pushed 页→右滑→true;卡死→false(maxSteps 用尽);中途 stop→false。
