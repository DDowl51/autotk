# 交付日操作手册（Mac + VPS 一条龙）

> 从零到「买家扫码即装、能激活、能养号发布」的完整顺序。预计半天。
> 分两台机器：**VPS**（部署 license）和 **Mac**（出手机包）。桌面管理中心在你的 Windows 上照旧。
>
> 顺序不能乱：**先有 license 域名地址，才能填进手机包**；**先改对 bundleId，才能 prebuild**。

---

## 阶段 A — 部署 license（VPS，先做）

完整步骤见 [license-部署手册.md](license-部署手册.md)。做完你手上要有三样东西：

- `EXPO_PUBLIC_LICENSE_URL` = `https://license.你的域名.com`
- `EXPO_PUBLIC_LICENSE_PRODUCT_KEY` = 后台建 autotk 产品拿到的 key
- `EXPO_PUBLIC_LICENSE_PRODUCT_SECRET` = 建产品时**只显示一次**的 secret

⛔ 没拿到这三样之前，不要开始阶段 C（填 env）。

---

## 阶段 B — 修 app.json（Mac，prebuild 之前必须做）

### B1. ⚠️ 改 bundleId（不改，装机台重签必失败）

`apps/mobile/app.json` 现在是 `"bundleIdentifier": "com.anonymous.autotk"`，
但装机台的 Apple 通配 App ID 是 `com.ddowl.*`、买家手册里写的也是 `com.ddowl.autotk`。**两者必须一致**。

改成：

```json
"bundleIdentifier": "com.ddowl.autotk"
```

> 若你的 Apple 账号通配符不是 `com.ddowl.*`，那就三处对齐成你自己的：app.json、
> Apple 开发者后台的通配 App ID、`services/signing-station` 的 config。

### B2. OTA 热更：自建（代码层已接好，这里只剩两步 Mac 动作）

OTA 已用**自建**方式接好：`package.json` 已加 `expo-updates`、`app.json` 已配 `updates`
（指向 `https://updates.你的域名.com/api/manifest`）+ `runtimeVersion: "1.0.0"` + 代码签名；
更新服务器是 `services/update-server`（详见 [远程更新方案.md](远程更新方案.md)）。首个包必须做两件事：

```bash
cd apps/mobile
pnpm install
# 1) 生成代码签名密钥对（一次性；证书打进 App、私钥给更新服务器）
npx expo-updates codesigning:generate-keypair \
  --key-output-directory code-signing --certificate-output-directory code-signing
#    → code-signing/certificate.pem 留着；code-signing/private-key.pem 移到更新服务器 data/secrets/
```

```
# 2) 把 app.json 里 updates.url 的「你的域名」换成真实更新服务器域名
"url": "https://updates.<你的真实域名>/api/manifest"
```

> `runtimeVersion` 用了固定字符串 `"1.0.0"`：**改原生（加模块/权限/升 SDK）时手动 +1 并重出包**，
> 纯 JS 修复不用动。更新服务器可以交付后再部署，但上面这两步**必须在首个 Release 包里定死**
> （证书要打进包、域名要写进包，事后加只能重出包重装）。
>
> 若这次不想接代码签名：删掉 app.json 的 `updates.codeSigningCertificate` + `codeSigningMetadata`
> 两行（仅靠 HTTPS，日后想加需重出包）。

### B2.5. 同一次 prebuild 里必须一起改的三处（漏了要再来一整轮 Mac 打包+全设备重装）

1. **App 图标**：`apps/mobile/assets/icon.png` 目前是 Expo 模板默认灰色同心圆——
   买家主屏会看到一个开发脚手架占位图。换成正式图标（同时换 adaptive-icon/splash）。
2. **本地网络权限文案**：`app.json` 的 `ios.infoPlist` 里补一条——
   `"NSLocalNetworkUsageDescription": "用于在同一 WiFi 下发现并连接管理中心、接收要发布的视频"`。
   缺它，买家首次连管理中心时 iOS 弹「查找并连接本地网络设备」且**没有解释文案**，
   非技术买家很可能点「不允许」→ 之后连不上电脑、收不到发布任务，且极难自查。
3. **强化 check-release**（可选）：现在 `check:release` 只挡空值/占位符，
   放行了 `http://` 和内网 IP（正是上次把 192.168.10.16 烤进包的原因）。
   有空就让它额外拒绝 `http://` 和私网段，避免再次误打内网地址。

### B3. 提交这两处改动

```bash
cd "I:/projects/开发tk养号-发布自动化"
git add apps/mobile/app.json apps/mobile/eas.json
git commit -m "chore(mobile): 交付配置——bundleId 对齐 com.ddowl.autotk + 接 expo-updates"
git push origin master:main
```

## 阶段 C — 填 env（Mac）

编辑 `apps/mobile/.env`（这文件被 gitignore，不进仓库，手改）：

```bash
EXPO_PUBLIC_LICENSE_URL=https://license.你的域名.com
EXPO_PUBLIC_LICENSE_PRODUCT_KEY=<阶段A的key>
EXPO_PUBLIC_LICENSE_PRODUCT_SECRET=<阶段A的secret>
EXPO_PUBLIC_HUB_URL=            # 留空——手机靠扫码/UDP自动发现连桌面Hub，不写死
EXPO_PUBLIC_TELEMETRY_URL=      # 要静默遥测就填你的 collector 地址，否则留空
# ⚠️ 确保没有 EXPO_PUBLIC_DEV_TOOLS=1（有它=正式包仍带「跳过激活」入口）
```

跑校验（占位符/漏填会 exit 1）：

```bash
cd apps/mobile && npm run check:release
```

---

## 阶段 D — prebuild（Mac）

```bash
cd apps/mobile
npx expo prebuild -p ios --clean     # 重新生成 ios/ 原生工程（autolink 原生模块 + 写入新 bundleId/updates 配置）
npx pod-install ios
```

> `--clean` 会删掉旧的 ios/ 重建。改过 bundleId、加过 expo-updates，这步必须重来一遍。

## 阶段 E — 出未签名 Release 母包（Mac）

装机台要的是**未签名 IPA**（它自己 ad-hoc 重签）。用 xcodebuild 出，不用 Xcode 点：

```bash
cd apps/mobile/ios

# 1. archive（关闭签名，出未签名 .xcarchive）
xcodebuild archive \
  -workspace autotk.xcworkspace \
  -scheme autotk \
  -configuration Release \
  -archivePath ./build/autotk.xcarchive \
  -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO

# 2. 把 .app 打成未签名 ipa（Payload 结构）
cd build
mkdir -p Payload && rm -rf Payload/*
cp -r autotk.xcarchive/Products/Applications/autotk.app Payload/
zip -qr autotk.ipa Payload
echo "母包：$(pwd)/autotk.ipa"
```

> scheme/workspace 名默认是 `autotk`（= app.json 的 slug）；不确定用
> `xcodebuild -list -workspace autotk.xcworkspace` 查实际 scheme 名。
> archive 报签名错就确认 `CODE_SIGNING_ALLOWED=NO` 两个都加了。

**同时**为了真机冒烟测试，装一个能连你 Mac 调试的 dev build（下一阶段要用）：

```bash
cd apps/mobile
npx expo run:ios --device --configuration Release   # 选你的测试 iPhone；这步会签名装到真机
```

> 冒烟测试用**这台真机上的 Release dev build**，不是母包本身——母包是给装机台重签分发的。
> 两者 JS 一致，冒烟通过即代表母包逻辑没问题。

## 阶段 F — 真机冒烟四件套（测试 iPhone）

装好后逐条验，**任何一条不过就别交付**：

1. **激活**：首启 → 输激活码 → 激活成功进主界面 → 杀 App 重开 → 免激活直接进。
   （顺带确认正式包**没有**「跳过激活」入口——有就是 C 阶段 DEV_TOOLS 没清干净）
2. **养号 + 保活**：TikTok 登录好、停干净视频页标定本机 → 点启动 → 自动刷/赞/评 →
   **锁屏或切后台 30 秒以上再回来**，日志应继续（保活生效）；点停止 → 几秒收尾、**不再切回 TikTok**。
3. **发布**：管理中心给这台发一条视频 → 手机日志走 `发布①…⑧`、TikTok 里真发出去 → 回推荐流。
   再发一条确认第二次也行。**发布中途点停止** → 该任务报 `failed（已请求停止）`。
4. **重连韧性**：手机连管理中心（同 WiFi/扫码）→ 关掉管理中心再开 → 手机自动重连、状态回来。

> 有条件的话，第 2 条**放一整夜**再看早上还在不在跑——这是产品核心承诺，唯一能真验的方式。

## 阶段 G — 母包进装机台并重启（装机台服务器）

```bash
# 1. 把阶段 E 的 autotk.ipa 覆盖过去
cp autotk.ipa <仓库>/services/signing-station/apps/autotk.ipa

# 2. ⚠️ 必须重启——签名缓存在内存，不重启会继续发旧包
cd services/signing-station && docker compose restart signing-station

# 3. 换包后体检（验母包结构 + 各账号 ASC 连接/证书）
pnpm --filter signing-station check
```

然后用测试机走一遍买家装机流程（[买家手册](买家手册.md)第六节）：Safari 开装机页 →
登记 → 安装 → 信任开发者 → 能激活能养号。**这一步过了才算真交付。**

## 顺序速查

```
VPS：  [A] 部署 license ──► 拿到 URL/key/secret
                                     │
Mac：  [B] 改 bundleId+接OTA ──► [C] 填 .env ──► [D] prebuild ──► [E] 出未签名母包 + dev build

```

## ⛔ 交付打包红线（别把源码目录整个打包给买家）

买家要的是**跑起来的软件**（手机装 IPA、电脑装管理中心），**不是整个仓库源码**。
若图省事把工作区目录压成 zip 交付，会连**真实凭据**一起送出去：

- `services/signing-station/data/secrets/*.p8 / *.p12` —— 你的 **Apple 签名私钥**（泄漏＝别人能冒用你的开发者账号签名）。
- `apps/mobile/.env` / `services/license/.env` —— 真实 license product secret、JWT。
- `hub-data/`、`apps/mobile/adaptation/screenshots/` —— 你的测试设备 ID、截图。

这些都已被 `.gitignore` 挡在 git 外（`git clone` 拿不到），但**「压缩工作区目录」会绕过 gitignore**。
交付只给：① 手机装的 `autotk.ipa`（走装机台扫码）② 电脑的管理中心安装包/启动包。
真要给源码，用 `git archive` 或干净 clone，别用 `zip 整个文件夹`。
