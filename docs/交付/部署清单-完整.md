# 完整部署清单（一份走完所有系统）

从零把整套系统部署上线要做的**每一步**。照着从上往下做即可。
标记约定：〖…〗=**你要替换的占位符**；【机器】=在哪台机器做；⚠️=踩坑点。

> 涉及三类机器：**VPS**（云服务器，跑 4 个后端服务）、**Mac**（出 iPhone 安装包）、**Windows**（跑管理中心 + 打两个工具）。
> Hub **不用单独部署**——它内嵌在桌面管理中心里，开管理中心就自动起。telemetry-collector 可选，本清单不含。

---

## 第 0 步 · 先备齐这些（不备后面每步都卡）

### 0.1 域名与 DNS（3 个子域名，各指向对应 VPS，放行 80/443）

| 子域名 | 指向哪个服务 | 用途 |
|---|---|---|
| 〖license.你的域名〗 | license 服务器 | 激活授权后台 + 客户端心跳 |
| 〖install.你的域名〗 | 装机台服务器 | 买家扫码装 autotk/WDA |
| 〖updates.你的域名〗 | 更新服务器 | OTA 热更（可后置部署，但域名要先定） |

> 三者可以在同一台 VPS（用不同域名 + 反代），也可分开。Caddy 会自动向 Let's Encrypt 签 HTTPS，**前提是域名 DNS 已生效 + 80/443 通**。

### 0.2 凭据清单（准备好、放对位置、绝不提交/绝不打进交付包）

| 凭据 | 从哪来 | 放哪 |
|---|---|---|
| Apple ASC API key（`.p8` + issuerId + keyId） | Apple Developer 后台 → Users and Access → Integrations → App Store Connect API | 装机台 `services/signing-station/data/secrets/` |
| iOS 重签证书（`.p12` + 口令） | Apple 证书 → openssl 转 p12（见 `WDA_STANDALONE.md` 付费段） | 装机台 `services/signing-station/data/secrets/` |
| Apple 通配 App ID `com.ddowl.*` | Apple 后台 → Identifiers → App IDs → Wildcard | （只是注册，无文件） |
| license `JWT_SECRET` | `openssl rand -hex 32` 生成 | license 服务器 `.env` |
| OTA 代码签名 `private-key.pem` | Mac 上 `expo-updates codesigning:generate-keypair` 生成 | 更新服务器 `data/secrets/` |

> ⚠️ `services/signing-station/data/`、各 `.env`、OTA 私钥都被 `.gitignore` 挡在 git 外。
> **交付给买家时只给安装包，绝不把仓库工作区打成 zip**（会绕过 gitignore 泄漏这些私钥）。

### 0.3 各机器装好基础工具

- **VPS**（每台）：Docker + docker compose（`curl -fsSL https://get.docker.com | sh`）。
- **Mac**：Xcode、Node ≥18、pnpm、`npm i -g eas-cli`（可选）、Apple 开发者账号已登录 Xcode。
- **Windows**：Node ≥18、pnpm、Python 3.9+（仅打「激活WDA」exe 时的构建机需要）。

## 第 1 步 · 部署 license 授权服务【VPS】

> 目标：买家能用激活码激活、你能在后台发码。细节与代码一致（`services/license`）。

```bash
# 1.1 拉代码（license 目录自包含，不依赖 monorepo）
git clone 〖你的私有仓库〗 app && cd app/services/license

# 1.2 建 .env：生成强随机 JWT_SECRET
#     ⚠️ 不设或用默认值，服务会「拒绝启动」（main.ts 的安全守卫）——见 1.6 排障
printf 'JWT_SECRET=%s\n' "$(openssl rand -hex 32)" > .env

# 1.3 收紧安全（编辑 docker-compose.yml）：
#     · 删掉 db 服务的 ports 映射 "55432:5432"（Postgres 默认口令 postgres/postgres，别对公网开）
#     · api 端口改成只 bind 本机： "127.0.0.1:3001:3001"（对外走 Caddy）

# 1.4 确认 JWT_SECRET 已插值（应是 64 位十六进制，不是 change-me-in-prod）
docker compose config | grep JWT_SECRET

# 1.5 起服务（api 容器会自动 prisma db push 建表）
docker compose up -d --build
docker compose logs -f api          # 看到 "license API on :3001" 即成功
```

**1.6 若 api 反复重启（crash-loop）** 且日志是「拒绝启动：JWT_SECRET 未设置或仍为公开默认值」：
说明 `.env` 没被读到 / 键名写错 / openssl 未装导致上面那行写空。修好 `.env`（确认与 `docker-compose.yml` 同目录、
内容确为 `JWT_SECRET=<64位十六进制>`）后 `docker compose up -d --build` 重来。

```bash
# 1.7 建首个管理员（等 db healthy 再跑；ADMIN_PASS 用强密码——系统暂无强制改密，别先用默认再改）
docker compose ps                   # 等 db 显示 healthy
docker compose exec -e ADMIN_USER=admin -e ADMIN_PASS='〖强密码〗' api node dist/seed.js

# 1.8 时钟同步（客户端验签有 5 分钟时间窗，时钟漂移=全体激活失败）
timedatectl set-ntp true && timedatectl
```

**1.9 构建并上传管理后台**（在开发机 / 本仓库根目录）：

```bash
pnpm install
pnpm --filter @license/web build                       # 产物 apps/web/dist（纯静态）
ssh 〖user@vps〗 'mkdir -p /srv/license-web'             # 先建目录，避免 scp 错放进子目录
scp -r apps/web/dist/* 〖user@vps〗:/srv/license-web/    # index.html 落在第一层
```

**1.10 Caddy 同源反代 + HTTPS**【VPS】（后台是相对路径请求 + 无 CORS，**必须同源**）：

```bash
apt-get install -y caddy
cat >/etc/caddy/Caddyfile <<'EOF'
〖license.你的域名〗 {
  handle /admin* { reverse_proxy 127.0.0.1:3001 }
  handle /v1*    { reverse_proxy 127.0.0.1:3001 }
  handle {
    root * /srv/license-web
    file_server
    try_files {path} /index.html
  }
}
EOF
systemctl reload caddy
curl -i -X POST https://〖license.你的域名〗/admin/login   # 应回 400/401（走到了 API）；回 HTML 则反代顺序错
```

**1.11 建产品 + 发码**（浏览器开 `https://〖license.你的域名〗`，用 1.7 的账号登录）：

1. 「产品」页 → 新建产品，名字 `autotk`。⚠️ **secret 只在建成那一刻显示一次**，立刻抄下 `key` 和 `secret`
   （丢了只能重置，重置后所有已打包客户端全失效）。
2. 「激活码」页 → 选 autotk → 批量生成：`count`（≤1000/次）、`maxDevices`（每码可绑几台，默认 1）、
   有效期（留空=永久）→ 导出 CSV 交付。

**1.12 备份**（激活码/绑定关系全在库里，务必定期）：

```bash
docker compose exec db pg_dump -U postgres license | gzip > /backup/license-$(date +%F).sql.gz
```

**license 产出 3 个值**，第 5 步回填手机：`EXPO_PUBLIC_LICENSE_URL=https://〖license.你的域名〗`、
`EXPO_PUBLIC_LICENSE_PRODUCT_KEY=〖key〗`、`EXPO_PUBLIC_LICENSE_PRODUCT_SECRET=〖secret〗`。

## 第 2 步 · 部署装机台 signing-station【VPS】

> 目标：买家用 Safari 扫码就能装 autotk / WDA（UDID 自动注册 + ad-hoc 重签）。细节见 `services/signing-station/README.md`。

```bash
cd services/signing-station

# 2.1 放凭据（第 0.2 步准备的）
mkdir -p data/secrets apps
cp 〖你的〗/AuthKey_XXXX.p8   data/secrets/     # ASC API key
cp 〖你的〗/acct1.p12         data/secrets/     # 重签证书

# 2.2 填 config.json（照 config.example.json 改）：
#     · 账号池：每个 Apple 账号一组 issuerId/keyId/.p8 路径 + .p12 路径/口令
#     · apps.wda.bundleId   = com.ddowl.WebDriverAgentRunner.xctrunner
#       apps.wda.motherIpaPath = apps/wda.ipa   (requiresXctest: true)
#     · apps.autotk.bundleId = com.ddowl.autotk
#       apps.autotk.motherIpaPath = apps/autotk.ipa

# 2.3 放两个母包进 apps/：
#     · apps/wda.ipa    ← 跑 .github/workflows/build-wda.yml 云编译（Xcode 14.3.1）下载的产物
#     · apps/autotk.ipa ← 第 5 步 Mac 出的未签名母包（先占位，出好再覆盖）

# 2.4 Apple 后台建通配 App ID com.ddowl.*（Identifiers → App IDs → Wildcard），并把手机 UDID 注册进去
#     （装机台会自动注册新 UDID，但账号要有权限）

# 2.5 改 Caddyfile 里的域名占位为 〖install.你的域名〗（itms 装 App 强制 HTTPS，必须域名+证书）

# 2.6 体检 + 起服务
pnpm --filter signing-station check          # 逐账号验 ASC 连接/证书 + 母包结构（含 WDA 的 XCTest）
docker compose up -d                          # signing-station:4100 + Caddy 自动 TLS
```

**2.7 验证**：手机 Safari 开 `https://〖install.你的域名〗/ota/autotk` → 见「安装 autotk」落地页，
「第一步：开始登记」下载描述文件 → 装 → 回落地页「第二步：安装」亮起 → 装上。

⚠️ **换了 autotk/WDA 母包后必须重启**（签名产物缓存在内存，不重启会继续发旧包）：
```bash
cd services/signing-station && docker compose restart signing-station
```

## 第 3 步 · 部署 OTA 更新服务器 update-server【VPS】

> 目标：日后出 bug 能远程热更 JS。可**交付后再部署**（第二版才用到），但第 5 步出包前要先有**签名密钥 + 域名**。
> 细节见 `services/update-server/README.md`。

```bash
cd services/update-server
mkdir -p data/updates data/secrets

# 3.1 放 OTA 代码签名私钥（第 5 步 Mac 生成的 private-key.pem）
cp 〖你的〗/private-key.pem data/secrets/private-key.pem

# 3.2 改 Caddyfile 域名占位为 〖updates.你的域名〗（必须与手机 app.json 的 updates.url 同域）

# 3.3 起服务（compose 已固定 UPDATES_DIR=/data/updates、私钥 /data/secrets/private-key.pem、KEYID=main、PORT=4200）
export BASE_URL=https://〖updates.你的域名〗
docker compose up -d --build
curl -s http://127.0.0.1:4200/healthz         # {"ok":true} 即起来了
```

**3.4 发一次热更**（日后修 JS 用；在 Mac 上）：

```bash
cd apps/mobile && npx expo export --platform ios       # 产出 dist/
ssh 〖user@vps〗 'mkdir -p /srv/update-server/data/updates/1.0.0'   # = compose 目录下的 data/updates
scp -r dist/ 〖user@vps〗:/srv/update-server/data/updates/1.0.0/$(date +%F-%H%M)/
# 手机下次冷启动 autotk 自动拉取（取该 runtimeVersion 下最新的文件夹）。无需重启服务。
```

> ⚠️ 目标目录是 **docker compose 挂载的 `data/updates`**，不是 `/srv/.../updates`——放错了 `/api/manifest` 恒 404、手机永远收不到。
> ⚠️ **runtimeVersion 纪律**：JS 热更只能推同 `runtimeVersion`（现 "1.0.0"）的包。改了原生（加模块/权限/升 SDK）必须升版号 + 重出母包走装机台，否则会把不兼容 JS 推给旧原生 → 崩溃。

## 第 4 步 · 出 iPhone 母包 autotk.ipa【Mac】

> ⚠️ 顺序不能乱：**先有 license 域名（第 1 步）才能填 .env；先有 OTA 域名+密钥才能定死进包**。

```bash
cd apps/mobile
pnpm install

# 4.1 改 bundleId：app.json 的 "bundleIdentifier": "com.anonymous.autotk" → "com.ddowl.autotk"
#     （与装机台 config.json 的 com.ddowl.autotk、Apple 通配 App ID 三处对齐）

# 4.2 生成 OTA 代码签名密钥对（一次性；证书打进 App、私钥给更新服务器）
npx expo-updates codesigning:generate-keypair \
  --key-output-directory code-signing --certificate-output-directory code-signing
#   → code-signing/certificate.pem 留着（随 App 打包，可提交）
#   → code-signing/private-key.pem 移到更新服务器 data/secrets/（勿提交、勿进 App）

# 4.3 把 app.json 的 updates.url 占位域名改成真实：
#     "url": "https://〖updates.你的真实域名〗/api/manifest"

# 4.4 换 App 图标：assets/icon.png 现在是 Expo 模板灰色占位图，换成正式图标（连带 adaptive-icon/splash）

# 4.5 填 .env（域名地址，不是内网 IP！）
cat > .env <<'EOF'
EXPO_PUBLIC_LICENSE_URL=https://〖license.你的域名〗
EXPO_PUBLIC_LICENSE_PRODUCT_KEY=〖第1.11步的key〗
EXPO_PUBLIC_LICENSE_PRODUCT_SECRET=〖第1.11步的secret〗
EXPO_PUBLIC_HUB_URL=
EXPO_PUBLIC_TELEMETRY_URL=
EOF
#   ⚠️ 确保没有 EXPO_PUBLIC_DEV_TOOLS=1（有它=正式包仍带「跳过激活」入口）

# 4.6 出包前校验（挡占位符/漏填；但它不挡 http/内网 IP，需你肉眼再确认 LICENSE_URL 是 https 域名）
npm run check:release

# 4.7 提交这两处（bundleId + OTA 证书）
cd 〖仓库根〗 && git add apps/mobile/app.json apps/mobile/code-signing/certificate.pem && git commit -m "交付配置" && git push

# 4.8 重生成原生工程（会把 EXUpdatesEnabled 翻 true、autolink keepalive/vision-ocr 原生模块）
cd apps/mobile
npx expo prebuild -p ios --clean
npx pod-install ios

# 4.9 出未签名母包（装机台自己会重签）
cd ios
xcodebuild archive -workspace autotk.xcworkspace -scheme autotk -configuration Release \
  -archivePath ./build/autotk.xcarchive -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO
cd build
mkdir -p Payload && rm -rf Payload/* && cp -r autotk.xcarchive/Products/Applications/autotk.app Payload/
zip -qr autotk.ipa Payload
echo "母包：$(pwd)/autotk.ipa"

# 4.10 顺带装一台真机做冒烟（Release dev build）
cd .. && npx expo run:ios --device --configuration Release
```

**4.11 母包进装机台**（把 4.9 的 autotk.ipa 覆盖过去 + 重启，见第 2.6/2.7）：
```bash
cp autotk.ipa 〖仓库〗/services/signing-station/apps/autotk.ipa
cd 〖仓库〗/services/signing-station && docker compose restart signing-station && pnpm --filter signing-station check
```

## 第 5 步 · 打桌面管理中心安装包【Windows】

> Hub 内嵌，无需单独部署。已接 electron-builder（主进程用 esbuild 打成自包含 bundle，绕开 pnpm 打包坑）。

```bash
pnpm install                                   # 首次（会拉 electron-builder，较大，需网络）
pnpm --filter @mc/shared build                 # 三个 workspace 包先出 dist（供 bundle 引用）
pnpm --filter @mc/hub build
pnpm --filter @mc/publisher build
pnpm --filter @mc/desktop dist                 # = build renderer + esbuild 打 main + electron-builder --win
# 产物：apps/desktop/release/TKManager-Setup-<版本>.exe  ← 发给买家双击安装
```

- 想快速验证不出安装包：`pnpm --filter @mc/desktop pack` → `apps/desktop/release/win-unpacked/`，直接跑里面的 exe 冒烟。
- ⚠️ 缺任一 `build` dist → electron 主进程 require 失败或白屏。
- ⚠️ **打完在真 Windows 上装一次、跑一次**：确认能起、能看到设备、能发视频、内嵌 Hub 起来（数据落 `%APPDATA%/TK管理中心/hub-data`）。
- 开发期照旧 `pnpm --filter @mc/desktop dev:renderer` + 另开 `electron`（用 `electron/main.cjs`，不打包）。

## 第 6 步 · 打「激活WDA」工具【Windows】

> 手机重启后要重新激活 WDA。已做成**完全自包含 exe**（Python + pymobiledevice3 全内置），买家零安装。

```bash
cd apps/mobile/tools
# 在一台装了 Python 3.9+ 的 Windows 上，双击 build-激活WDA.bat（自动 pip 装 pyinstaller+pymobiledevice3 再打包）
# 产物：dist\ActivateWDA.exe（约 86MB，完全自包含）
```

- **不需要 go-ios**（挂开发者镜像用 pymobiledevice3；装 WDA 走装机台）。
- ⚠️ 打完在一台**没装 Python 的干净 Windows** 上双击测一次（冻结 pymobiledevice3 偶尔缺 hidden import，
  报 `ModuleNotFoundError: xxx` 就在 bat 里加一条 `--collect-all xxx` 重打）。
- 交付：把 `ActivateWDA.exe` 拷到买家电脑桌面、重命名「激活WDA」。
