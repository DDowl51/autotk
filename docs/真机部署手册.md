# autotk 2.0 部署、工作流测试与问题反馈手册

> 当前唯一部署入口。最后核对：2026-07-23。
> 适用当前主线：`desktop + master + perception + WDA + TikTok`；发布再加 `receiver`。
> 已退役的 `apps/mobile`、逐机坐标标定、手机端引擎、License 门禁与 OTA 不属于 2.0 部署。

本文按“先得到最小可运行链路，再逐层放大”的顺序组织：

1. 选择一种部署拓扑；
2. 部署 GPU 感知服务；
3. 准备 WDA 与手机；
4. 安装或启动 desktop；
5. 先做无副作用冒烟，再单次运行一个工作流；
6. 出错时自动/手动留证，并按固定模板反馈；
7. 最后才扩到多机与发布。

---

## 0. 先选拓扑：两种方式只能选一种

### 0.1 推荐：desktop 托管 master

这是日常使用与交付的默认方式。

```text
Ubuntu 24.04 GPU 机
└─ services/perception :8000

Windows 控制电脑
└─ TK 管理中心
   ├─ 内嵌 Hub
   ├─ 内嵌 master
   ├─ 自动扫描手机 :8100
   └─ 发布接收通道 :4610

iPhone × N
├─ WDA :8100
├─ TikTok
└─ receiver（仅发布需要）
```

desktop 安装包已经包含 `master.cjs`，不要求买家另装 Node/pnpm。打开 desktop 后，它会自动启动 Hub 与 master、扫描 WDA 手机，并把 master stdout/stderr 写进 desktop 当日日志。

**不要再手工启动第二份 master。** 两份 master 会争用同一台手机的 WDA 会话，测试现象会变得不可解释。

### 0.2 工程调试：手动运行 master

只在需要看终端、改源码或测试 headless 部署时使用。

```text
GPU/控制机
├─ services/perception :8000
└─ services/master

Windows 控制电脑（可选）
└─ desktop 仅作 Hub/看板，必须关闭 master 自动启动
```

若同时打开 desktop，启动前设置：

```powershell
$env:MASTER_AUTOSTART="0"
pnpm --filter @mc/desktop electron
```

然后只启动一份手动 master。此模式下 receiver 必须连接**实际运行 master 的电脑** `:4610`。

## 1. 环境与端口

### 1.1 机器

| 角色 | 推荐环境 | 必需 |
|---|---|---|
| GPU 感知机 | Ubuntu 24.04、NVIDIA GPU、系统 Python 3.12、可访问模型目录 | 是 |
| 控制电脑 | Windows 10/11 x64；与手机同局域网 | 是 |
| 构建电脑 | Node.js 22+、pnpm 10.28.0；只在源码开发/打包时需要 | 开发时 |
| Mac | Xcode + Apple 签名；构建 receiver 时需要 | 发布功能 |
| 手机 | iPhone、TikTok 已登录、WDA 已签名安装 | 是 |

生产 GPU 环境锁 Ubuntu 24.04；原生 Windows/WSL 可用于临时验证，但不是当前生产基线。

### 1.2 网络

| 端口 | 方向 | 用途 |
|---|---|---|
| TCP 8000 | 控制电脑 → GPU 机 | perception OpenAI 兼容端点 |
| TCP 8100/每台手机 | master → iPhone | WDA |
| TCP 4610 | receiver → master | 视频下载命令与进度 |
| desktop 自动选择 | desktop/手机 | 内嵌 Hub 与局域网文件服务 |

要求：

- 控制电脑、手机处于同一可互访局域网；
- 路由器不要开启 AP/客户端隔离；
- 手机建议做 DHCP 静态租约；
- Windows 防火墙允许 TK 管理中心访问专用网络；
- GPU 防火墙放行来自控制网段的 TCP 8000；
- 测试时手机保持解锁、TikTok 前台、自动锁定设为“永不”。

## 3. 部署 perception（GPU 感知服务）

### 3.1 创建 Python 环境

以下命令在 Ubuntu 24.04 GPU 机执行。该系统默认 Python 3.12，不要直接安装仓库里通常不存在的 `python3.11` 包。已有能跑 LocateAnything 的 venv 时可直接复用，只补 `requirements.txt`。

```bash
sudo apt update
sudo apt install -y git python3 python3-venv

cd /opt
git clone <仓库地址> autotk
cd /opt/autotk

python3 --version
python3 -m venv .venv-perception
source .venv-perception/bin/activate
python -m pip install -U pip wheel

pip install "torch==2.11.0" "torchvision==0.26.0" --index-url https://download.pytorch.org/whl/cu128
pip install "transformers==4.57.1" "huggingface_hub>=0.34,<1.0" "Pillow==11.1.0" decord lmdb
pip install -r services/perception/requirements.txt

python -m pip freeze > perception-environment.txt
```

`perception-environment.txt` 是本机环境快照，排障时随日志保存，不提交仓库。`decord/lmdb/FastAPI` 当前未完全锁死，因此这一步是可追溯快照，不代表仓库已经提供完整 Python lock。

确认 PyTorch 看到 GPU：

```bash
python -c 'import torch; print(torch.__version__); print(torch.cuda.get_device_name(0)); print(torch.cuda.get_device_capability(0))'
```

RTX 5060 Ti 应能看到 Blackwell capability `(12, 0)`。若 `torch.cuda.is_available()` 为假，先修 NVIDIA 驱动/CUDA PyTorch 轮子，不要继续排查 master。

### 3.2 准备模型

把 `nvidia/LocateAnything-3B` 下载到稳定目录，例如：

```bash
mkdir -p /opt/models
huggingface-cli download nvidia/LocateAnything-3B \
  --local-dir /opt/models/LocateAnything-3B
```

网络受限时可在能下载的机器完成后原样拷贝模型目录。不要把模型放进仓库。

### 3.3 启动

```bash
cd /opt/autotk
source .venv-perception/bin/activate

python services/perception/server.py \
  --model /opt/models/LocateAnything-3B \
  --attn sdpa \
  --max-side 640 \
  --temperature 0.7 \
  --host 0.0.0.0 \
  --port 8000
```

当前事实：

- LocateAnything 是单目标模型，`batch=1`；
- 多目标请求由客户端在同一截图上逐个单查；
- 生产默认长边 640；
- 小目标（尤其约 15px 的关闭按钮）不稳时，重启服务改为 `--max-side 768` 后复测；
- FP8/flash-attn 不是当前生产路径，不要在首次部署时启用。

### 3.4 健康检查

GPU 本机：

```bash
curl http://127.0.0.1:8000/health
```

控制电脑：

```powershell
curl.exe http://<GPU_IP>:8000/health
```

通过标准：

```json
{"ok":true,"max_side":640}
```

若本机通、控制电脑不通，只查路由/防火墙；若 `ok:false`，说明服务在但模型尚未加载成功。

### 3.5 生产常驻

先用前台进程完成真机联调，确认无误后再配置 systemd。下面示例创建专用用户并给代码/模型最小读取权限；若使用已有部署用户，必须同时把 `User=` 和目录权限改成该用户。

```bash
sudo useradd --system --user-group --home-dir /opt/autotk --shell /usr/sbin/nologin autotk
sudo chown -R autotk:autotk /opt/autotk
sudo chgrp -R autotk /opt/models/LocateAnything-3B
sudo chmod -R g+rX /opt/models/LocateAnything-3B
for group in video render; do
  getent group "$group" >/dev/null && sudo usermod -aG "$group" autotk
done
```

若 `video` 或 `render` 组在该机器不存在，不要盲目创建；用 `ls -l /dev/nvidia*` 核对设备节点实际所属组。

systemd 示例：

```ini
# /etc/systemd/system/autotk-perception.service
[Unit]
Description=autotk perception
After=network-online.target

[Service]
Type=simple
User=autotk
WorkingDirectory=/opt/autotk
ExecStart=/opt/autotk/.venv-perception/bin/python services/perception/server.py --model /opt/models/LocateAnything-3B --attn sdpa --max-side 640 --temperature 0.7 --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now autotk-perception
sudo journalctl -u autotk-perception -f
```

## 4. 准备 WDA 与 iPhone

### 4.1 得到 WDA IPA

仓库 `.github/workflows/build-wda.yml` 固定 Appium WebDriverAgent `v15.1.3`，可产出未签名 `WebDriverAgent.ipa`；构建日志会打印精确 commit。工作流使用 Xcode 14.3.1 作为 iPhone 8 / iOS 16 基线，但仍须以本次 Actions 成功和装机台 preflight 为准。

WDA 母包必须保留 XCTest frameworks 与 `.xctest` 插件；`signing-station check` 会校验。不要采用旧文档中“删除 XCTest 框架”的做法。

安装前还需要用 Apple 开发证书与包含目标 UDID 的 profile 重签。单机开发可用 Xcode/Sideloadly；量产安装可用 `services/signing-station`，命令级步骤见 [`交付/装机台-1panel部署手册.md`](交付/装机台-1panel部署手册.md)。

### 4.2 Windows 安装设备工具

1. 安装 Apple Devices 或 iTunes，让 Windows 得到 Apple USB 驱动；
2. 数据线连接 iPhone、解锁并选择“信任此电脑”；
3. 安装 go-ios：

```powershell
npm install -g go-ios@1.2.0
ios --help
ios version
ios list
```

`ios list` 必须能列出手机后再继续。
本文固定记录过的 go-ios 版本为 `1.2.0`。安装、子命令和 iOS 17+ tunnel 变化以 [官方 README](https://github.com/danielpaulus/go-ios) 为准；升级工具后先在一台测试机复核命令，再批量替换。

### 4.3 安装并启动 WDA

```powershell
ios install --path=<已签名的WebDriverAgent.ipa>
```

手机端完成：

- 设置 → 通用 → VPN 与设备管理 → 信任开发者；
- 设置 → 隐私与安全性 → 开发者模式；
- 重启手机；
- 设置 → 显示与亮度 → 自动锁定 → 永不。

先准备开发者镜像：

```powershell
ios image auto
```

iOS 16 在一个保持运行的 PowerShell 中启动 WDA：

```powershell
ios runwda `
  --bundleid=<WDA真实bundleId> `
  --testrunnerbundleid=<WDA真实bundleId> `
  --xctestconfig=WebDriverAgentRunner.xctest
```

iOS 17+ 在 Windows 需要：

1. 从 [Wintun 官方站](https://www.wintun.net/) 下载架构匹配的 `wintun.dll`，复制到 `C:\Windows\System32`；
2. 以管理员身份打开 PowerShell，运行 `ios tunnel start` 并保持终端；
3. 另开管理员 PowerShell，用 `ios tunnel ls` 确认设备 tunnel；
4. 再运行同一条 `ios runwda ...`。

macOS/Linux 的 tunnel 命令按 go-ios 官方说明使用 `sudo ios tunnel start`。先用一台目标版本手机跑通，再复制到机群；不要把 iOS 16 与 iOS 17+ 的守护方式混用。

`ios runwda` 终端需保持运行，USB/XCTest 会话也需保持。每台手机建议独立终端或进程守护。

### 4.4 验证

```powershell
curl.exe http://<手机WiFi_IP>:8100/status
```

通过标准：返回 JSON 且包含 ready/session 信息。必须从**运行 master 的电脑**再测一次，避免只在 WDA 宿主机本地可达。

TikTok 要求：

- 国际版已登录；
- 能正常加载内容；
- 首次测试使用专门测试账号；
- 关闭自动更新，避免联调中途 UI 变版；
- 不要在生产账号上首次验证点赞、评论、私信或发布。

## 5. 构建或安装 desktop

### 5.1 从源码打 Windows 安装包

在 Windows 仓库根执行：

```powershell
pnpm --filter @mc/shared build
pnpm --filter @mc/hub build
pnpm --filter @mc/publisher build
pnpm --filter @mc/desktop dist
```

产物在：

```text
apps/desktop/release/TKManager-Setup-1.0.0.exe
```

`dist` 会生成：

- renderer；
- Electron 主进程；
- preload；
- 自包含 `master.cjs`；
- NSIS 安装包。

### 5.2 源码联调

终端 1：

```powershell
pnpm --filter @mc/shared build
pnpm --filter @mc/hub build
pnpm --filter @mc/publisher build
pnpm --filter @mc/desktop dev:renderer
```

终端 2：

```powershell
$env:VITE_DEV_SERVER_URL="http://localhost:5173"
pnpm --filter @mc/desktop electron
```

### 5.3 首次配置

打开 desktop → 设置 → 后台识别与设备发现：

- GPU 识别服务地址：`http://<GPU_IP>:8000`；
- 扫描网段：手机所在 `/24` 前三段，例如 `192.168.11`；
- 多个网段用逗号分隔，例如 `192.168.1,192.168.11`；
- 留空网段时 master 会从本机私网网卡自动推断；
- 点击“保存并重启后台”。

正确状态应依次出现：

1. master：运行中；
2. 当前 VLM 地址正确；
3. 正在扫描的网段正确；
4. 上次扫描时间更新；
5. 发现手机数大于 0；
6. 上线手机数大于 0；
7. 最近一次错误为“无”。

初扫和持续重扫并发度由 master 控制；默认每 20 秒重扫，新开的 WDA 会自动加入。

## 6. 手动 master（仅工程调试）

推荐 desktop 托管；只有需要终端时才使用本节。

### 6.1 配置

```powershell
cd D:\autotk\services\master
Copy-Item devices.example.json devices.local.json
```

真实配置含 UDID/IP，文件名使用 `*.local.json`，已被 gitignore。

最小结构：

```json
{
  "vlm": {
    "url": "http://192.168.1.9:8000",
    "model": "locateanything-3b"
  },
  "staggerMs": 3000,
  "schedule": { "allDay": true, "windows": [] },
  "params": {
    "searchKeywords": ["fitness tips"],
    "postReplies": false,
    "dm": {
      "dmEnable": false,
      "dmKeywords": [],
      "dmTemplates": [],
      "dmDailyCap": 2
    }
  },
  "devices": [
    {
      "id": "test-01",
      "udid": "真实UDID",
      "host": "192.168.1.51",
      "name": "测试机01"
    }
  ]
}
```

### 6.2 启动

纯工作流，不接 desktop/Hub：

```powershell
$env:MASTER_CONFIG="./devices.local.json"
pnpm --filter @mc/master start
```

连接指定 Hub 与发布链路：

```powershell
$env:HUB_URL="http://<控制电脑IP>:4000"
$env:MASTER_CONFIG="./devices.local.json"
pnpm --filter @mc/master start
```

自动发现模式：

```powershell
$env:MASTER_DISCOVER="1"
$env:MASTER_SUBNET="192.168.11"
$env:MASTER_VLM_URL="http://<GPU_IP>:8000"
pnpm --filter @mc/master start
```

不要同时运行 desktop 托管的 master。

## 7. 最小链路冒烟：先不跑完整工作流

### 7.1 无副作用定位

TikTok 停在能看到目标的页面：

```powershell
cd D:\autotk\services\master
$env:WDA_URL="http://<手机IP>:8100"
$env:VLM_URL="http://<GPU_IP>:8000"
$env:TARGET="feed.like-off"
Remove-Item Env:TAP -ErrorAction SilentlyContinue
pnpm smoke
```

产物：

```text
services/master/smoke-shot.png
```

通过标准：

- 输出 `✅ 命中`；
- 坐标中心落在当前未点赞白心上；
- 没有发生点击。

### 7.2 明确授权后真点

只用测试账号：

```powershell
$env:TAP="1"
pnpm smoke
```

通过标准：手机目标真实变化，且下一张截图能观察到变化。

### 7.3 640 精度地板

至少逐个验证：

- `feed.like-off`
- `feed.save-off`
- `nav.search-icon`
- `comments.input`
- `ad.shop-promo`
- `browser.inapp`
- 实际出现时的系统权限按钮

`ad.shop-promo` 等小关闭按钮在 640 下不稳时，先把 perception 改为 768 重测。不要先改工作流坐标；2.0 的坐标来源是 VLM。

## 8. 单次运行一个工作流

持续运行的 `master start` 不适合复现问题。当前提供一次性入口：指定一台手机、指定工作流，只跑一轮并自动留证。

### 8.1 运行前

1. 关闭 desktop，或确保 `MASTER_AUTOSTART=0`；
2. 配置文件只放一台测试机；
3. `schedule.allDay=true`；
4. `postReplies=false`；
5. `dm.dmEnable=false`；
6. TikTok 使用测试账号；
7. perception 与 WDA 健康检查已通过。

### 8.2 搜索互动

配置中必须有 `searchKeywords`：

```powershell
cd D:\autotk\services\master
pnpm workflow:test -- `
  --config ./devices.local.json `
  --device test-01 `
  --workflow search
```

### 8.3 关注监控

配置中必须有 `following.moduleEnable=true`：

```powershell
pnpm workflow:test -- `
  --config ./devices.local.json `
  --device test-01 `
  --workflow followMonitor
```

前置：测试账号已关注有内容的账号。

### 8.4 主页 + 私信

配置中必须有 `persHome.moduleEnable=true`：

```powershell
pnpm workflow:test -- `
  --config ./devices.local.json `
  --device test-01 `
  --workflow profileAndDM
```

第一轮保持 `dmEnable=false`，只验证主页、作品与评论导航。需要验证私信时：

- 只对自己的另一测试账号；
- `dmDailyCap` 设为 1；
- 使用无营销风险的测试话术；
- 记录“按钮不存在 / 被平台拦截 / 发送成功”三种结果；
- 当前 StateStore 是内存实现，重启后去重/日限额不持久，不能把它当生产防重保证。

### 8.5 自动产物

默认写入：

```text
services/master/test-artifacts/<时间>-<设备>-<工作流>/
├─ run.log
├─ events.jsonl
├─ summary.json
├─ before.png
├─ after.png
└─ failure.png        # 失败时尽力生成
```

`summary.json` 只记录 UDID 末 4 位，不落完整硬件标识；搜索词、用户名、评论/私信文本仍可能出现在运行日志或截图中，反馈前必须继续按 11.4 脱敏。

也可指定产物根目录；runner 仍会在根目录下创建唯一时间戳子目录：

```powershell
pnpm workflow:test -- `
  --config ./devices.local.json `
  --device test-01 `
  --workflow search `
  --artifacts D:\autotk-test-runs\search-001
```

退出码：

- `0`：工作流与留证流程正常结束；仍需按 `summary.json`、手机结果和截图判断业务是否达标；
- `1`：接线、WDA/VLM 或工作流失败，证据仍会尽力落盘；
- `2`：CLI 参数错误；按帮助修正命令后重跑。

### 8.6 desktop 手动工作流测试

需要验证“Hub 下发 + 远程启停”时：

1. 设备页选择该手机；
2. 先选“停（不跑）”；
3. 批量设置里配置关键词、概率、回复/私信安全值；
4. 工作流下拉框选择 `搜索互动 / 关注监控 / 主页+私信`；
5. 点击“启动”；
6. 达到本轮验收点后立即“停止”；
7. 打开设备详情观察状态与实时日志；
8. 出错先留证，再重启后台。

这条路径测试的是管理中心接线；一次性 CLI 测试的是工作流本身。两者不要混为一个通过项。

## 9. 发布链路

发布比养号多一条硬依赖：视频必须先进入 iOS 相册，因此每台手机还需 receiver。

### 9.1 当前诚实边界

`apps/receiver/App.tsx` 目前通过构建期环境变量读取：

- `EXPO_PUBLIC_MASTER_URL`
- `EXPO_PUBLIC_UDID`

其中 `EXPO_PUBLIC_UDID` 实际必须等于 master/Hub 使用的 **deviceId**：

- 配置表模式：等于 `devices[].id`；
- 自动发现模式：等于当前生成的 `auto-<IP末段>`。

因此：

- 单机可以按设备构建、安装和验证；
- 同一个 receiver IPA 暂不能直接分发给 N 台并在手机端运行时配置；
- 自动发现身份与真实 UDID 尚未统一；
- 在 receiver 支持运行时配置和稳定身份前，**发布的多机量产部署没有闭环**。

不要在文档或验收中把“发布纯逻辑测试通过”写成“多机发布已经可交付”。

### 9.2 单机构建

在 Mac：

```bash
cd apps/receiver
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck

export EXPO_PUBLIC_MASTER_URL=http://<运行master的电脑IP>:4610
export EXPO_PUBLIC_UDID=test-01

npx expo prebuild --platform ios
npx expo run:ios --device
```

授权：

- 相册：全部照片；
- 定位：始终允许；
- 本地网络：允许。

通过标准：receiver 显示“已连 master”，desktop 下发发布后依次出现下载中、已存相册、TikTok 发布中、published。

### 9.3 desktop 文件夹发布

1. 设置 → 视频根文件夹；
2. 根目录下子文件夹名等于 desktop 中的设备名；
3. 放入 `mp4/mov/m4v`；
4. 可放同名 `.txt` 文案；
5. 发布页“扫描”；
6. 对测试机发送一条；
7. 验证 receiver 入相册、TikTok 真发布、desktop 终态为 published；
8. 再验去重，已发布视频不得重复发送。

## 10. 多机扩量

必须按 1 → 2 → 小批量 → 目标规模扩，不要第一次就扫满网段。

每次扩量都记录：

- 发现数与上线数；
- 每台 WDA 是否稳定；
- perception 请求延迟与队列；
- 工作流完成率；
- 每台最近错误；
- Wi-Fi AP 负载；
- GPU 利用率与显存；
- 是否出现串机、双 master 或同一时间峰值。

`staggerMs` 默认 3000ms。单卡承载不能只按“手机在线数”判断，要按真实工作流的 VLM 调用频率和失败重试量测。

## 11. 出问题时怎么记录和反馈

### 11.1 先留证，再重启

失败发生后按顺序：

1. 在 desktop 只暂停出问题的手机；
2. 记下精确时间（到分钟）、设备名、工作流；
3. 记录最后一个成功步骤；
4. 写清“期望结果”和“实际结果”；
5. 手机原生截图；
6. 截图 desktop 设置页的后台状态与最近错误；
7. 打开设备详情保存相关日志；
8. 设置页点击“打开日志目录”，复制当天 `app-YYYY-MM-DD.log`；
9. 一次性 runner 则直接保留整个 test-artifacts 目录；
10. 留证完成后再点击“重启后台”。

desktop 的 `lastError` 是内存状态，重启会清空；日志文件不会。

### 11.2 手动进程落盘

PowerShell：

```powershell
New-Item -ItemType Directory -Force D:\autotk-test-runs\run-001 | Out-Null

pnpm --filter @mc/master start *>&1 |
  Tee-Object D:\autotk-test-runs\run-001\master.log
```

perception 与 `ios runwda` 也各自用 `Tee-Object` 保存到同一目录。Linux：

```bash
python services/perception/server.py ... 2>&1 | tee perception.log
```

### 11.3 每次反馈必须包含

- 测试编号；
- git commit；
- desktop 版本；
- Node/pnpm/Python 版本；
- GPU/OS；
- iPhone 型号、iOS、TikTok 版本；
- go-ios 版本、WDA ref/commit 与 bundleId；
- deviceId 与工作流；
- 复现步骤；
- 期望/实际；
- 最后成功步骤；
- 精确发生时间；
- `summary.json` / `events.jsonl` / `run.log`；
- before/after/failure 手机截图；
- desktop 当日日志；
- `perception-environment.txt` 与 perception/WDA 日志；
- 是否可稳定复现。

可直接复制填写 [`真机联调-checklist.md`](真机联调-checklist.md)。

### 11.4 脱敏

不要直接发送：

- `devices.json` / `*.local.json` 原文件；
- 完整 UDID；
- Apple 凭据、`.p8/.p12`、profile；
- TikTok 密码、私信对象、真实营销话术；
- 视频原文件。

发送前替换：

- UDID 只保留末 4 位；
- 内网 IP 可改成 `<PHONE_IP>/<GPU_IP>`；
- 搜索词、用户名、文案改成 `<REDACTED>`；
- 日志里若含私信/评论内容也要脱敏。

## 12. 常见问题定位表

| 现象 | 先看 | 常见原因 |
|---|---|---|
| perception `/health` 不通 | GPU 服务终端、8000 防火墙 | 模型未加载、端口未放行、地址填错 |
| master 未运行 | 设置页最近错误、desktop 当日日志 | bundled master 缺失、Hub 未起、旧进程未退出 |
| 扫描网段不对 | 设置页“正在扫描的网段” | VPN/多网卡、未手填手机网段 |
| 发现 0 台 | 从控制电脑 curl 手机 `:8100/status` | WDA 未起、手机锁屏、AP 隔离、防火墙 |
| 发现数 > 0，上线数为 0 | master 日志、WDA 会话 | WDA 建会话失败、两份 master 抢会话 |
| 手机上线但不跑 | 工作流、运行时段、参数 | `activeWorkflow=off`、搜索词为空、不在时段、被暂停 |
| 坐标偏/小按钮 miss | smoke-shot、640/768 对比 | VLM phrase/region 或 640 精度不足 |
| 工作流安静返回但没完成 | runner before/after/events | Step 返回非 ok 后业务提前结束；按最后成功步骤定位 |
| 设备详情无实时日志 | master 是否以该 deviceId 注册、Hub 连接 | master 已转发工作流/WDA 日志，但 Hub 只保留内存；完整证据仍用当日日志/runner 产物 |
| receiver 离线 | receiver UI、`:4610` 地址、deviceId | 连错 master 主机、构建期 ID 不匹配 |
| 发布失败 | receiver 进度、发布进度、手机相册 | receiver 未存相册、权限未给、TikTok 页面变化 |

## 13. 当前上线边界

已能自动化验证：

- core/driver/perceptor/plugin 纯逻辑；
- master 配置、发现、Hub、接收端编排；
- desktop 渲染层、后台状态逻辑与类型；
- receiver 下载/状态机纯逻辑。

仍必须真机完成：

- 640 下逐目标精度；
- 三个养号工作流真实端到端；
- 系统弹窗与 TikTok 变版；
- WDA 长会话；
- 私信平台限制；
- receiver Mac 构建、后台保活、入相册；
- 单机发布；
- 多机 Wi-Fi/GPU 承载。

仍是工程缺口：

- Postgres StateStore；当前 DM 去重/限量重启后不持久；
- receiver 运行时配置与稳定设备身份；当前阻塞多机发布量产。

因此，自动化测试全绿可以写“离线门禁通过”，不能写“真机上线通过”。
