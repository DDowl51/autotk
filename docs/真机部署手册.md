# autotk 2.0 · 真机部署手册(命令级)

> 日期:2026-07-20　目标:从零把整套系统部署到真机并跑通(养号 + 管理中心 + 发布)。
> **每一步都给确切命令**。占位符:`<GPU_IP>`(GPU 主机 LAN IP)、`<CTRL_IP>`(控制 PC LAN IP)、`<PHONE_IP>`(手机 WiFi IP)、`<UDID>`(手机 UDID)。全部机器在**同一局域网**。
> 命令环境:Windows 用 **PowerShell**;GPU 若走 Linux/WSL 用 **bash**;Mac 用 **zsh/bash**。

---

## 0. 拓扑与前置

### 机器角色(可合并)
| 代号 | 机器 | 跑什么 | 备注 |
|---|---|---|---|
| **A** | GPU 主机 | perception 感知服务 + master 主控 | 需 NVIDIA GPU;Windows 原生或 Ubuntu 24.04 |
| **B** | 控制 PC(Windows) | desktop 管理中心(**内嵌 Hub :4000**) | 可与 A 同机(A 是 Windows+GPU 时最省) |
| **C** | Mac | 构建两个 IPA(WDA + 收视频端) | 一次性;非越狱 iPhone 装 App 必需 |
| **D** | iPhone × N | WDA + TikTok + 收视频端 App | 同 WiFi |

> **最省配置(推荐先跑通)**:A+B 合成一台 **Windows + NVIDIA GPU** 的机器,再加一台 Mac、一台 iPhone。跑通了再扩机器/手机。

### 账号 / 前置
- [ ] 一个 **Apple ID**(签 WDA + 收视频端 App 到非越狱机必需;免费账号 7 天签,长期用付费或走装机台)。
- [ ] 路由器可设 **DHCP 静态租约**(给每台手机固定 IP)。
- [ ] 各机互通:部署完后能互相 `ping` / `curl`。

## 1. 【C · Mac】构建两个 IPA(一次性,先做——装机要用)

Mac 装 **Xcode**(App Store)+ 命令行工具:`xcode-select --install`。装 Node + pnpm:
```bash
brew install node
npm i -g pnpm
```

### 1.1 拿仓库
```bash
git clone <你的仓库地址> ~/autotk
cd ~/autotk
```

### 1.2 收视频端 App(apps/receiver)
```bash
cd ~/autotk/apps/receiver
pnpm install
pnpm test                      # 纯逻辑自检:8 测试全绿(可选)
npx expo prebuild --platform ios   # 生成 ios/ 原生工程
```
用 Xcode 打开签名构建:
```bash
open ios/*.xcworkspace
```
- Xcode 里:选 **Signing & Capabilities** → 勾 **Automatically manage signing** → 选你的 Team(Apple ID)。
- 选目标设备(接上的 iPhone)→ **Product → Archive** → **Distribute App → Ad Hoc / Development** → 导出 `receiver.ipa`。
- (或省事:直接 **Product → Run**,Xcode 会把 App 装到接着的手机上——但每台都要连 Mac 跑一次。)

### 1.3 WDA(WebDriverAgent)IPA
> WDA 是 Appium 的驱动 App,独立于本仓库。两条路:
- **(推荐)项目装机台**:`services/signing-station` 的 `/ota/wda` 扫码即装(云编译母包已含 XCTest)。见 `services/signing-station/README.md`。
- **(手动)Xcode 构建**:克隆 `https://github.com/appium/WebDriverAgent`,Xcode 打开 `WebDriverAgent.xcodeproj` → 选 `WebDriverAgentRunner` target → Signing 选你的 Team → 改 bundleId 唯一 → **Product → Build for Testing**,或用 go-ios 直接跑(见第 2 步)。

## 2. 【D · 每台 iPhone】装机(新机做一遍)

> **2.0 手机只需 WDA + TikTok + 收视频端 App**,比旧系统轻:**不装旧 autotk、不要激活码、不用标定**。

在能连手机的电脑(Mac 或装了驱动的 Windows)上操作。以下用跨平台的 **go-ios**:
```bash
npm i -g go-ios
ios list                        # 列出设备,拿到 <UDID>
```
> Windows 需先装 **iTunes 或「Apple 设备」App**(苹果 USB 驱动),手机连线解锁点「信任此电脑」。

### 2.1 装 WDA + 收视频端
```bash
ios install --path=WebDriverAgent.ipa       # 装 WDA
ios install --path=receiver.ipa             # 装收视频端(1.2 导出的)
```
手机上:设置 → 通用 → VPN与设备管理 → **信任开发者证书**(两个都信任);设置 → 隐私与安全性 → **开发者模式** → 开 → **重启**。

### 2.2 挂开发者镜像 + 起 WDA
```bash
ios image auto                              # 自动下载并挂载对应 iOS 版本镜像
ios runwda --bundleid=<WDA的bundleid> --testrunnerbundleid=<...Runner> --xctestconfig=WebDriverAgentRunner.xctest
# runwda 需保持运行、手机保持 USB 连着(维持 XCTest 会话)
```
**验 WDA 通**(另开一个终端,手机在 WiFi 上):
```bash
curl http://<PHONE_IP>:8100/status          # 返回含 "ready"/sessionId = 成功
```

### 2.3 TikTok + 收视频端 + 系统设置
- [ ] TikTok:登录好账号、能正常刷视频(建议关 TikTok 自动更新)。
- [ ] 打开**收视频端 App** → 授**相册「全部照片」+ 定位「始终」**(系统弹窗点允许)。
      装机时配好它的两个变量(打包时注入,或用 EAS/Expo config):
      `EXPO_PUBLIC_MASTER_URL=http://<GPU_IP>:4610`、`EXPO_PUBLIC_UDID=<该机编号>`。
- [ ] 设置 → 显示与亮度 → **自动锁定 → 永不**;手机常插电、亮度调低。**屏一锁自动化就停。**

### 2.4 网络定型
- [ ] 路由器给该手机 MAC **绑 DHCP 静态租约**(固定 `<PHONE_IP>`)。
- [ ] 记下每台的 `<UDID>` / `<PHONE_IP>` / 编号,填进第 4 步的 `devices.json`。

## 3. 【A · GPU 主机】感知服务 perception

> 本节两条路线二选一。**路线 A 原生 Windows** 最快(bench 实测与 Linux 同速);**路线 B WSL2 Ubuntu 24.04** 与生产一致(D5)。

### 3.0 装工具链(Windows,若还没有)
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned; irm get.scoop.sh | iex
scoop install git nodejs
npm i -g pnpm
# Python 3.11:从 python.org 装(勾 Add to PATH),验证:
python --version    # 应 3.11.x 或 3.12.x
```

### 3.1 拿仓库 + 装依赖
```powershell
git clone <你的仓库地址> D:\autotk
cd D:\autotk
pnpm install
pnpm --filter "@auto/*" --filter @mc/master test    # 离线自检:@auto 201 + master 53 全绿
```

### 3.2 路线 A · 原生 Windows 起感知服务
```powershell
cd D:\autotk\services\perception
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   # 必须 cu128(认 Blackwell)
pip install "transformers==4.57.1" "huggingface_hub<1.0" pillow torchao
pip install -r requirements.txt                       # fastapi/uvicorn/pydantic
python -c "import torch; print(torch.cuda.get_device_name(0), torch.cuda.get_device_capability(0))"  # 应打印卡名 + (12, 0)

# 下模型(被墙走镜像):
$env:HF_ENDPOINT="https://hf-mirror.com"
huggingface-cli download nvidia/LocateAnything-3B --local-dir .\LocateAnything-3B

# 起服务(生产分辨率 640、温度 0.8 已是默认):
python server.py --model .\LocateAnything-3B --attn sdpa --max-side 640 --port 8000
```
> 路线 B(WSL2 Ubuntu 24.04):按 `docs/LocateAnything-3B-5060Ti-性能报告.md` §9 建 Python 3.11 venv + 同款依赖,`python server.py --model ./LocateAnything-3B --attn sdpa --max-side 640 --port 8000`。

### 3.3 验感知服务
```powershell
curl http://localhost:8000/health           # {"ok":true,"max_side":640}
```
记下 GPU 主机 LAN IP(`ipconfig`)= `<GPU_IP>`,后面 master/手机用 `http://<GPU_IP>:8000`。

## 4. 【A · GPU 主机】主控 master

### 4.1 写设备配置表
```powershell
cd D:\autotk\services\master
copy devices.example.json devices.json
notepad devices.json
```
按第 2 步记的信息填(真实 devices.json **已 gitignore**,不会误提交):
```jsonc
{
  "vlm": { "url": "http://<GPU_IP>:8000", "model": "locateanything-3b" },
  "staggerMs": 3000,
  "schedule": { "allDay": false, "windows": [
    { "start": "07:00:00", "end": "11:00:00" },
    { "start": "12:00:00", "end": "16:00:00" },
    { "start": "17:00:00", "end": "22:00:00" }
  ]},
  "params": {
    "searchKeywords": ["你的关键词"],
    "posPrompts": ["*"],
    "dm": { "dmEnable": true, "dmKeywords": ["合作","咨询"], "dmTemplates": ["你好 {user} 🙌"], "dmDailyCap": 20 }
  },
  "devices": [
    { "id": "01", "udid": "<UDID>", "host": "<PHONE_IP>", "name": "iPhone-01" }
  ]
}
```
> `params` 是全局默认;每台可加 `"params": {...}` 深合并覆盖(如某台不同关键词)。`activeWorkflow` 不用在这里填——从管理中心下拉框选(见第 6 步)。

### 4.2 起 master(接管理中心 + 发布)
> 前提:第 3 步 perception 起着;第 2 步各手机 WDA 跑着 + TikTok 前台;第 5 步 desktop(含 Hub)起着(HUB_URL 指向它)。
```powershell
cd D:\autotk\services\master
$env:HUB_URL="http://<CTRL_IP>:4000"          # 指向 desktop 内嵌 Hub(A+B 同机时用 http://localhost:4000)
$env:MASTER_CONFIG="./devices.json"
pnpm --filter @mc/master start
```
起来会:探活各手机(不可达即报)→ 装配 Fleet → 注册每台到 Hub → 5s 上报状态 → 收工作流/启停/发布任务。收视频通道监听 `:4610`(手机端收视频 App 连它)。
> 纯养号不接管理中心:不设 `HUB_URL` 即可(此时无看板/无发布)。

## 5. 【B · 控制 PC】管理中心 desktop(内嵌 Hub)

> desktop 的 electron 主进程**内嵌 Hub**(端口 4000),并每 3s 向局域网广播发现信标。需先构建三个包的 CJS dist。

### 5.1 构建依赖(desktop 主进程 require 它们的 dist)
```powershell
cd D:\autotk
pnpm --filter @mc/shared build
pnpm --filter @mc/hub build
pnpm --filter @mc/publisher build
```

### 5.2 起 desktop(开发运行,最快)
两个终端:
```powershell
# 终端 1:渲染层(Vite :5173)
pnpm --filter @mc/desktop dev:renderer
```
```powershell
# 终端 2:Electron(加载渲染层 + 起内嵌 Hub :4000)
$env:VITE_DEV_SERVER_URL="http://localhost:5173"
pnpm --filter @mc/desktop electron
```
> 打包成安装包(可选,给非开发机用):`pnpm --filter @mc/desktop dist`(electron-builder → `apps/desktop/release/` 出 Windows 安装包)。

### 5.3 确认 Hub
- desktop 窗口右上角/设置里能看到「已连接」。默认连 `http://localhost:4000`(内嵌 Hub)。
- master 的 `HUB_URL` 要指向**这台控制 PC** 的 `:4000`(A+B 同机=localhost;分开=`http://<CTRL_IP>:4000`)。
- 记下 `<CTRL_IP>`(`ipconfig`)。

## 6. 端到端联通 + 冒烟

按顺序确认(便宜→贵):

- [ ] **感知服务**:`curl http://<GPU_IP>:8000/health` → ok。
- [ ] **每台手机 WDA**:`curl http://<PHONE_IP>:8100/status` → ready。
- [ ] **master 起来**:日志里各手机「✅ 可达 分辨率」、无「不可达」。
- [ ] **看板出设备**:desktop「设备」页出现每台手机、状态转绿。
- [ ] **单目标冒烟(可选,先验精度)**:另开终端,TikTok 停在能看到点赞键的页:
      ```powershell
      $env:WDA_URL="http://<PHONE_IP>:8100"; $env:VLM_URL="http://<GPU_IP>:8000"; $env:TARGET="feed.like-off"
      pnpm --filter @mc/master smoke        # 看 smoke-shot.png 坐标准不准;加 $env:TAP="1" 真点
      ```
- [ ] **选工作流 + 启动**:desktop「设备」页 → 某台的**工作流下拉**选「搜索互动」→ **启停列点「启动」**。看该机开始跑(模块列变化、stats 增长)。
- [ ] **批量**:勾多台 → 工具栏「批量设工作流」+「批量启动/停止」。
- [ ] **私信**:配了 `dm` 的机跑「关注监控」或「主页+私信」,看板 stats「私信(成功/失败)」增长。
- [ ] **发布(需收视频端 App 就绪)**:desktop「发布」页 → 拖视频进文件夹 → 选设备 + 文案 → 定时/立即发。链路:桌面 LAN 直传 → master 令收视频端下载存相册 → master 驱动 TikTok 发布 → 看板发布进度到「published」。

## 7. 日常运维 + 排障

### 起停顺序
1. GPU:perception(先)。2. 控制 PC:desktop(内嵌 Hub)。3. 各手机:WDA(go-ios runwda 保持)。4. GPU:master。
> master 依赖 perception + Hub + 手机 WDA,**最后起**。停则反序。

### 常见问题
| 现象 | 排查 |
|---|---|
| master 报某台「不可达」 | 该手机 WDA 没跑 / IP 变了 / 不同网。`curl <PHONE_IP>:8100/status` 逐台验;确认 DHCP 静态租约生效 |
| 看板不出设备 | master 的 `HUB_URL` 指错(要指控制 PC 的 :4000);desktop 内嵌 Hub 没起(看终端 2 日志) |
| 定位不准/小 × 识别不到 | perception 换 `--max-side 768`(640 丢最小目标时);对不准的 Target 改 `plugin-tiktok/src/target-registry.json` 的 phrase(同步 docs/specs 副本) |
| 发布卡在 downloading | 收视频端 App 没连上 master(查 App 里状态「已连 master」);或 LAN 下载不通(手机与桌面同网否);超时会自动 failed 可重派 |
| 私信发不出 | TikTok 反垃圾拦截 / 对方无私信按钮(自动跳过记 dm-failed);看板「私信失败」数 |
| 工作流切换后卡在深页 | recoverToFeed 会逐级带回推荐流;连续失败会告警(看板 alert 列)。多次不行手动把 TikTok 退回推荐流 |
| GPU 显存不足/OOM | 锁 `--max-side 640`(已默认);单卡 ~10 台到顶就多卡分片 |

### 关键路径速查
- 感知服务:`services/perception/server.py`(`--max-side 640 --port 8000`)
- 主控:`services/master`(`HUB_URL` + `MASTER_CONFIG` + `start`;收视频通道 `:4610`)
- 管理中心:`apps/desktop`(内嵌 Hub `:4000`)
- 收视频端:`apps/receiver`(连 `EXPO_PUBLIC_MASTER_URL`)
- 配置表:`services/master/devices.json`(UDID↔IP↔编号,gitignore)
- 联调 checklist(逐目标精度等更细):`docs/真机联调-checklist.md`

## 8. 承载与扩容(心里有数)
- 单卡(RTX 5060 Ti)「纯 VLM 指令源」**~10 台**(裸 BF16 768;640 略高)。几百台 = 多卡分片。
- 真实瓶颈除算力外还有 **WiFi(多 AP)** 与 **WDA 长会话稳定性**——扩量前先小规模稳态跑。
- 详见 `docs/LocateAnything-3B-5060Ti-性能报告.md`、`docs/内网集中识别服务器-架构设计.md`。
