# 真机测试脚本

> 目的：拿到 iPhone（+ 视情况一台 Mac）后，照本文一步步验三件**代码已完成、但从未上真机**的事：
> **① 监控关注视频（打粉）· ② 真机连上 Hub · ③ 远程下发视频**。
> 每项都写清：前提 → 一步步操作 → **预期现象** → **不对时看哪里**。
> 更全的真机验收项见 `真机与上线收尾清单.md`；本文聚焦这三件的可执行流程。

## 0. 三项测试的依赖矩阵（先看这个，决定你要准备什么）

| 测试 | 需 iPhone | 需 WDA 起来 | 需标定坐标 | 需 Mac 出 App 母包 | 需桌面控制中心 | 需 license 后端 |
|---|---|---|---|---|---|---|
| ① 监控关注（走电脑 REPL） | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| ② 真机连 Hub | ✅ | ❌ | ❌ | ✅ | ✅ | ✅（App 有激活门禁） |
| ③ 远程下发视频 | ✅ | ✅（发布那步要驱动 TikTok） | ✅（尤其发布流程标定） | ✅ | ✅ | ✅ |

**结论**：**① 最好验**（只要手机 WDA + 电脑，不用 Mac）；**②③ 要先用 Mac 出一次 autotk dev build**，且 App 有激活门禁（需 license 后端或临时绕过）。

## 1. 通用前置

### 1.1 电脑侧软件
```bash
# 仓库根
pnpm install
# 手机端 autotk 是独立安装（不在 root workspace）
cd apps/mobile && pnpm install
```
- **ImageMagick**（`magick` 命令）：标定/OCR 裁图要用。`magick -version` 能出版本即可。
- 首次跑 OCR（calibrate 定位「关注」Tab）会自动下 tesseract 的 `eng`/`chi_sim` 语言包，需联网。

### 1.2 【地基 A】把 WDA 跑起来（①③ 必需）
详见 `apps/mobile/WDA_STANDALONE.md`。要点：
1. WDA 已签名装到手机；开**开发者模式** + 信任证书；
2. 挂开发者镜像并启动 WDA（iOS16：`go-ios image auto` 不要 tunnel；iOS17+ 见文档）；
3. 验证：`curl http://<手机IP>:8100/status` 返回 ready。
> 手机与电脑**同一 WiFi**；下面 `<手机IP>` 都填手机局域网 IP。

### 1.3 【地基 B】标定坐标（①③ 必需）
1. 手机 TikTok 停在**干净视频**（推荐页、没点赞、作者没关注、普通视频、背景别纯白）。
2. 电脑：
   ```bash
   cd apps/mobile
   WDA_URL=http://<手机IP>:8100 npm run wda:repl
   ```
3. REPL 里：
   ```
   calibrate      # 检测右栏 + 校验 + OCR 定位「关注」Tab，通过则存 adaptation/devices.json
   like           # 看手机是否点中爱心（现在还会按当前视频白带自动吸附）
   save
   detect         # 只检测打印、不写盘
   ```
   - 预期日志：`已标定 [375x667] 并保存`、`OCR 定位「关注」Tab → (x, y)`。
   - 若 `⚠ 标定被拒：…`：多半没停在干净视频页，换一条重试。
   - 若 OCR「未找到关注/Following Tab」：界面语言/位置不同，`followTab` 会用比例默认，先继续，测①时再看准不准。
4. **换机型/分辨率必须重标**（iPhone 8 是 `375x667`，与 `390x844` 不同）。

### 1.4 【地基 C】出 autotk dev build（②③ 必需，要 Mac）
autotk 用了原生模块（AsyncStorage / expo-camera 扫码 / react-native-udp 自动发现），**Expo Go 装不全**，必须 dev build：
```bash
cd apps/mobile
npx expo prebuild           # 生成原生工程（新增原生模块后必跑）
npx expo run:ios            # 连着 iPhone，编译并装上 dev build
```
> 没 Mac 时的**部分替代**：`npx expo start` 用 Expo Go 扫码——能验 socket.io 连接那一半（手填地址），但**扫码相机 / UDP 自动发现用不了**。
>
> **激活门禁**：App 首启要输激活码。要么先部署 license 后端（`services/license`，`docker compose up`）+ 建 `autotk` 产品 + 发一个码；要么临时把门禁放开（改 `src/license/config.ts` 的开关，仅测试用，别进正式包）。

### 1.5 【地基 D】起桌面控制中心（②③ 必需）
```bash
# 仓库根：先建三个内嵌 dist（桌面主进程 require 它们）
pnpm --filter @mc/shared build
pnpm --filter @mc/hub build
pnpm --filter @mc/publisher build
pnpm --filter @mc/desktop build
# 起 Electron（内嵌 Hub 随之自启）
pnpm --filter @mc/desktop electron
```
- 预期：顶栏出现绿点 +「控制中心运行中」；启动的终端打印「内嵌 Hub 已启动 :4000」。
- **设置 → 连接手机**：显示二维码 + `http://<本机局域网IP>:4000`。

## 2. 测试① 监控关注视频（打粉）

**目的**：验证 autotk 切到「关注」流、逐条进评论区、命中关键词的评论用固定话术回复。

### 2.1 前提
- 地基 A（WDA）+ 地基 B（标定）已完成；
- 该 iPhone 的 TikTok 账号**已关注若干账号**，且这些账号视频下**有评论**（否则没东西可回）。

### 2.2 临时开启 following 模块（REPL 用默认参数，following 默认是关的）
编辑 `apps/mobile/src/params/defaults.ts`（**仅测试临时改，测完可还原**）：
```ts
following: {
  moduleEnable: true,   // ← 改成 true（默认 false）
  // …其余不动。commentMatchKeywords / fixedReplies 留空=沿用全局
},
allDay: true,           // ← 改成 true，否则不在 taskWindows 时间段内引擎会空转
```
再确认**全局有关键词和话术可命中**（同文件里 `commentMatchKeywords`、`fixedReplies` 非空；打粉常用词如「加」「微信」「vx」「联系」；话术如「宝子加我 vx：{user}」）。

### 2.3 跑
```bash
cd apps/mobile
WDA_URL=http://<手机IP>:8100 npm run wda:repl
calibrate         # 先标定（含「关注」Tab OCR 定位）
run               # 启动引擎，Ctrl+C 停
```

### 2.4 预期现象（对着手机 + 看 REPL 日志）
- 日志出现 `[关注监控] 开始，计划查看 N 条关注视频`；
- 手机**顶部从「推荐」切到「关注」**流；
- 逐条视频：进评论区 → 日志 `评论解析：N 条` → 命中关键词的评论下发出话术 → 日志 `已发评论 @xxx：…`；
- **纯打粉模式**：开关打开后**只跑关注监控、不跑推荐/搜索/主页**（与养号互斥），所以你会看到它**一直在关注流**打粉、不会切去养号。

### 2.5 不对时看哪里
| 现象 | 看哪 |
|---|---|
| 没切到「关注」流 / 点偏了 | 「关注」Tab 坐标：`calibrate` 时 OCR 有没有命中；没命中就去 `adaptation/devices.json` 该分辨率的 `anchors.followTab` 手填 |
| 进了评论区但「评论解析：0 条」 | 评论区 OCR：`src/vision/detect.ts` 的 `detectCommentHearts` 区域 + `src/engine/commentParse.ts` 阈值，真机对着截图调 |
| 命中不回复 / 回复内容怪 | 关键词有没有配、`fixedReplies` 占位符展开：`src/gen` 的 `createFixedReplyGenerator` |
| 引擎不动 | 是不是 `allDay:false` 且不在时间段；`moduleEnable` 是否真改成 true |

## 3. 测试② 真机连上 Hub

**目的**：验证手机 autotk 扫码 / 自动发现连上桌面内嵌 Hub，出现在桌面设备页，且断线能自动重连。

### 3.1 前提
- 地基 C（App dev build 装好、能过激活门禁）+ 地基 D（桌面控制中心起来）；
- 手机与电脑**同一 WiFi**。

### 3.2 步骤
1. 桌面：**设置 → 连接手机**，看到二维码。
2. 手机 autotk：主界面「连接控制中心」→ **扫码**（扫桌面二维码）。
   - 或**自动发现**：同 WiFi 下手机不扫码，等几秒看是否自动连上（靠 UDP 广播）。
3. 连上后手机头部应显示**「已连接控制中心」**。
4. 桌面**总览 / 设备**页应**出现这台手机**（含在线、电量列）。

### 3.3 重连韧性（重点验，这是 P1 的卖点）
- **Hub 晚于手机起**：先开手机 App、后起桌面 → 桌面一起手机应自动接上；
- **Hub 重启 / IP 变**：桌面关掉重开、或换 WiFi 使本机 IP 变 → 手机应自动重连（socket.io 无限重试）；未连时手机头部显示「未连接控制中心」，本机照常跑。
- **端口占用回退**：先用别的程序占住 4000 再起桌面 → Hub 应落到 `HUB_PORTS` 表里下一个端口（51820…），二维码地址随之变；手机重连也应按同表兜底。

### 3.4 预期 & 排查
| 现象 | 看哪 |
|---|---|
| 扫码后连不上 | 二维码里的 IP 是不是手机能访问的本机局域网 IP；防火墙有没有放行该端口 |
| 自动发现不生效 | UDP 广播可能被路由器 AP 隔离/防火墙拦——退回扫码即可（属预期兜底） |
| 设备页不出现 | 手机头部是否「已连接」；桌面终端日志有无该设备的 `device:hello` |
| 断线不重连 | `apps/mobile/src/hub/client.ts` 的重连选项；端口兜底见 `hubUrl.ts` 的 `HUB_PORTS`（两端必须一致） |

## 4. 测试③ 远程下发视频

**目的**：桌面把视频下发到某台手机，手机下载入相册并发布到 TikTok。

> ⚠️ **先读这条**：**最后「发布到 TikTok」那步现在是骨架、坐标是占位的**（`publishVideo` 的 `publish*` 锚点没真机标定）。**没做发布流程标定前，别指望它真能正确发出去——会点偏甚至误操作。** 本测试**分两段**：先验能验的（下发 + 下载入相册 + 状态回传），发布那步单独标定后再验。

### 4.1 前提
- 地基 A/B/C/D 全部完成；手机已连上 Hub（测试②通过）。

### 4.2 摆好视频文件夹（桌面本机）
1. 建一个**根目录**，例如 `D:\autotk-videos\`。
2. 在根目录下建**以设备名命名**的子文件夹（设备名 = 桌面设备页显示的那个名字），例如 `D:\autotk-videos\手机1\`。
3. 把要发的视频（`.mp4/.mov/.m4v`）放进去。
4. 文案（可选）：`同名.txt`（如 `a.mp4` 配 `a.txt`）优先；或根目录放 `captions.txt` 做「文件名→文案」映射；都没有就用文件名当文案。

### 4.3 下发
1. 桌面 **发布** 页 → **视频根目录** 选到上面的根目录 → **扫描**。
2. 每台设备一张卡片，列出待发视频，每条有**「发送时间」**（留空=立即；已按错峰自动填好，可逐条改；有「错峰时间/全部立即」批量键）。
3. 点某条的**「发布/定时」**，或卡片右上**「全部发布」**。

### 4.4 预期现象（分两段看）
**A 段（现在应能通）**：
- 手机日志：`收到发布任务：xxx.mp4`；
- 手机**下载视频进相册**（局域网直传）；桌面「发布进度」状态依次：`待发/已下发 → 下载中 → 已入相册`。

**B 段（发布到 TikTok，标定前会点偏——预期不通，只看到它"尝试"）**：
- 手机日志：`已尝试发布（⚠ 上传流程坐标需真机标定核实）`；
- 实际会点偏。**要先做发布流程标定**（见 4.6）才能真发成功、状态走到 `已发布`。

### 4.5 排查
| 现象 | 看哪 |
|---|---|
| 手机收不到任务 | 手机是否「已连接控制中心」；桌面「未连接 Hub 无法下发」提示 |
| 下载不进相册 | 局域网直传/防火墙；`downloadToAlbum`（手机需相册权限，首次系统弹窗要允许）|
| 定时不触发 | 桌面（内嵌 Hub）需**保持开启**到点才下发；`services/hub/src/domain/publish-coordinator.ts` |
| 发布点偏（预期） | `publish*` 锚点未标定——见 4.6 |

### 4.6 发布流程标定（把 B 段做通，真机专项）
1. 手机手动进 TikTok 上传流程，逐屏截图；
2. 量出每个按钮坐标：`+`（创建）→ 上传/相册 → 相册第一条 → 下一步 → 文案框 → 发布；
3. 填进 `adaptation/devices.json` 该分辨率的 `anchors`：`publishCreate/publishUpload/publishAlbumFirst/publishNext/publishCaption/publishPost`；
4. 或后续做「进上传流再 OCR 定位『下一步/发布』文字键」的专门标定流程（`findAnchorByText` 已就绪，缺导航进上传流的接线）。
5. 标好后重跑 4.3，B 段应走到 `已发布`。

## 5. 排查速查表（跨测试通用）

| 症状 | 首查 |
|---|---|
| WDA 连不上 | `curl http://<手机IP>:8100/status`；镜像挂没挂、WDA 起没起 |
| 点击全偏 | 是否 `calibrate` 过、分辨率对不对（换机型要重标）|
| OCR 无结果 | `magick` 装没装；tesseract 语言包下没下（首次要联网）|
| 引擎空转 | `allDay:false` 且不在 `taskWindows` 时间段 |
| 手机没出现在桌面 | 同 WiFi？防火墙放行端口？手机头部「已连接」？ |
| 定时/发布不动 | 桌面控制中心是否保持开启到点 |
