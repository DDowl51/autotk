# L3 业务规格(G0)

autotk 2.0 的**决策/业务层**语义:参数、概率模型、分时段调度、四模块流程、评论逻辑。**语义照搬旧引擎,代码全新写**(总纲 §4 L3)。数值来自旧 `src/params/` + `src/engine/`,是本项目「拟人化防风控」的核心资产,不得随意改。

> 与下发面对齐:所有参数 = `packages/shared` 的 `ConfigPatch`(两端共用防漂移,既有纪律)。L3 只消费参数、不知道屏幕细节(经 L2 动作库操作)。

## 1. AutomationParams 字段树与默认值

约定:概率字段 ∈ `[0,1]`;次数/时间 ≥ 0。字段名刻意对齐原版 JSON。

### 1.1 顶层:关键词/提示词/开关

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `searchKeywords` | string[] | `[]` | 搜索关键词 |
| `posPrompts` | string[] | `["*"]` | 正向提示词:推荐页命中才互动。`"*"`=全互动;填词则只互动**文案命中**的视频(需 OCR) |
| `negPrompts` | string[] | `[]` | 反向提示词:推荐页命中立即划走 |
| `commentMatchKeywords` | string[] | `[]` | 评论匹配词:评论文字含任一词→优先回复该作者。空=不筛选(按概率回复) |
| `fixedReplies` | string[] | `["{love this\|so true\|needed this} {emoji}", "this is everything {emoji}", "facts {emoji}"]` | 固定话术模板(支持占位符,§6.2) |
| `kwSearchExecRatio` | number[0,1] | `0` | 搜索页占比(逐批伯努利概率,非精确时长)。默认 0=开箱即推荐页养号;>0 时校验强制配 `searchKeywords` |
| `clickWaitTime` | number(秒) | `1` | 每次点击间隔;校验须 `>0`(0=零延迟连点极易风控) |
| `postReplies` | boolean | `false` | 是否真发回复。false=只生成+日志预览不发送(先验 AI 质量);确认后设 true |
| `allDay` | boolean | `false` | 全天运行;false 则按 `taskWindows` 分段 |
| `taskWindows` | `{start,end}[]` | 4 段(见 §4) | 设备本地时 `"HH:MM:SS"`,1..N 段,排序不重叠 |

### 1.2 模块共用结构 `ModuleInteractionParams`(9 字段)

`interactEnable`(是否开评论区互动)· `interactProb`(命中后进评论区概率)· `videoLikeProb` · `videoSaveProb` · `videoFollowProb` · `commentLikeProb`(单条评论点赞概率)· `commentReplyProb`(单条评论回复概率,独立于点赞;风险更高故默认更低)· `commentLikeMaxCount`(单视频评论点赞上限)· `commentReplyMaxCount`(单视频评论回复上限)。

### 1.3 四模块默认值(⚠️ 均为「已降过的防风控值」,勿回调到原版)

| 字段 | forYou 推荐 | kwSearch 搜索 | persHome 主页 | following 关注监控/打粉 |
|---|---|---|---|---|
| moduleEnable | —(常开) | —(常开) | **false** | **false** |
| interactEnable | true | true | false | true |
| interactProb | 0.5 | 0.45(原版0.8) | 0.1 | **1**(打粉拉满) |
| videoLikeProb | 0.3 | 0.5 | **0** | **0** |
| videoSaveProb | 0.1 | 0.3 | **0** | **0** |
| videoFollowProb | 0.1 | 0.3 | **0** | **0** |
| commentLikeProb | 0.5 | 0.5 | 0.5 | 0.3 |
| commentReplyProb | 0.2 | 0.3 | 0.5 | **0.8**(命中词优先回) |
| commentLikeMaxCount | 4(原版15) | 5(原版30) | 4(原版20) | 3 |
| commentReplyMaxCount | 2 | 2 | 2 | 3 |

模块特有扩展字段:
- **persHome**:`moduleEnable`(账号无作品必须 false;每天最多一次)、`maxVideoCount`=`3`(进主页对多少条自己作品互动)。videoLike/Save/Follow 恒 0(不点自己作品)。
- **following**(关注监控/打粉):`moduleEnable`(开启=**纯打粉**,只跑关注流、与日常养号互斥)、`commentMatchKeywords`=`[]`(空=沿用全局)、`fixedReplies`=`[]`(空=沿用全局)。videoLike/Save/Follow 全 0。

### 1.4 校验规则(防呆,新代码须实现)

- 所有概率(含 `kwSearchExecRatio` + 四模块六个 prob)∈ `[0,1]`;否则报错。
- `clickWaitTime > 0`(挡 0 与 NaN)。
- `kwSearchExecRatio > 0` 但 `searchKeywords` 空 → 报错「启用搜索页但无关键词」。
- `persHome.moduleEnable` 真但 `maxVideoCount < 1` → 报错。
- **单视频评论互动硬上限**:`commentLikeMaxCount ≤ 30`、`commentReplyMaxCount ≤ 10`,不得为负;超限报「过大…防封号」。
- 时间窗:≥1 段;格式 `^([01]\d|2[0-3]):[0-5]\d:[0-5]\d$`;每段 `start<end`;按序不重叠。`timeToSeconds = h*3600+m*60+s`。

### 1.5 原版导入 fromLegacy(可选兼容,注意「另一套默认」)

从扁平 snake_case 转入;**legacy fallback 与新默认不同**,勿混:`kw_search_int_exec_prop`→`kwSearchExecRatio`(legacy fallback **0.8** vs 新 0)、`click_wait_time`→`clickWaitTime`(legacy **0.5** vs 新 1)、forYou.commentLikeMaxCount legacy 15 / kwSearch 30 / persHome 20、kwSearch.interactProb legacy 0.8、kwSearch.commentLikeProb 0.6。逗号分隔串 `splitList` 拆数组;`following`/`commentMatchKeywords`/`fixedReplies` 原版无 → 默认。**新系统是否保留 legacy 导入 = 待定**(旧用户迁移才需要)。

## 2. 概率模型(拟人化核心,精确复刻)

**`chance(p): boolean`** — `p≤0`恒 false;`p≥1`恒 true;否则 `Math.random() < p`(以概率 p 命中)。

**`jitter(seconds, ratio=0.3): number`**(返回秒数,不休眠)— `randFloat(seconds*(1-ratio), seconds*(1+ratio))`。默认 ±30%:`jitter(n)`∈`[0.7n, 1.3n)`。**所有等距停顿都过 jitter 拟人化**,新系统禁止裸用固定间隔。

工具:`randInt(min,max)`=闭区间整数;`randFloat`=`[min,max)`;`pick(arr)`=随机取一(空→undefined)。

**停顿一览(全部 ratio=0.3)**:批次间 `jitter(1.5)`;forYou/following 每视频后 `jitter(3)`;kwSearch/persHome 每视频后 `jitter(2)`;评论每次点赞/回复后 `jitter(clickWaitTime)`。

> ⚠️ 与承载量的关系:这些停顿正是「每台 VLM 间隔 6–8s / 盲滑后 10–13s」的来源(性能报告 §7.2)。**它们既是防风控、也是承载量的前提**,不可为提速砍掉。

## 3. 调度与主循环

### 3.1 分时段
- `isWithinAnyWindow`:当前「当天秒数」落在任一 `[start,end)`(左闭右开),设备本地时。
- `secondsUntilNextWindow`:今天下一段 start 差值;今天没了→到明天首段(`DAY - now + firstStart`);空窗→`+∞`。
- `allDay=true` 忽略窗、恒可运行。

### 3.2 主循环(每台一个,`while(!stopped)`)
启动前 `validateParams`,有错不启动。每轮:
1. **不在时段** → 打一次「等待到点」日志,睡 `min(secondsUntilNextWindow, 30)` 后 continue。
2. **被暂停**(发布正驱动同一手机前台)→ 睡 1s continue(养号与发布**串行不抢前台**)。
3. 否则开**批次**:`batchGen++`;`ctx.shouldStop = stopped || myGen!==batchGen`;`ctx.withinWindow = allDay||isWithinAnyWindow`;`ctx.params` 每次读最新(热更即时生效)。
4. 批次先 `recoverToFeed`(回推荐流基地)。
5. **模块选择(互斥优先级)**:
   - `following.moduleEnable` → **只跑 `runFollowingFeed`**(纯打粉,暂停一切养号);
   - 否则 `persHome.moduleEnable` 且今天没跑过(`persHomeRanOn !== todayKey()`)→ **先标记今天已尝试,再跑 `runPersHome`**(失败也不整天重试);
   - 否则 → `runGrooming`(推荐/搜索按占比)。
6. 批次末睡 `jitter(1.5)`。

### 3.3 占比分发(逐批伯努利,非配额)
`pickModule = chance(kwSearchExecRatio) ? "kwSearch" : "forYou"`。每批视频预算随机:推荐 `randInt(5,15)`、搜索 `randInt(3,8)`、关注监控 `randInt(3,8)`;主页由 `maxVideoCount`+实际作品数定,不参与抽样(每天一次单独触发)。

### 3.4 每日一次主页
`persHomeRanOn`(日期 key `YYYY-M-D`)。满足条件时**先写 key 再执行**(即便失败当天不重试);跨天可再跑。

### 3.5 可打断停止 / 容错(新系统须复刻这套自愈)
- `stop()` 置 `stopped` 并唤醒可打断休眠;`interruptibleSleep` 停止时立即返回;模块内每视频前查 `shouldStop`/`withinWindow`。
- **batchGen 机制**:模块超时(`MODULE_TIMEOUT=300s`)→ `batchGen++`,被弃批的 `shouldStop` **永久为真**(布尔复位会复活,故用单调代号),残留 await 下次检查即退,**绝不与新批并发驱动同一手机**(JS 无法取消在飞 await,这是最强保证)。
- **退避+熔断**:单批异常 `consecutiveErrors++`,退避 `min(60, 2^n)s`;连续 `5` 次 → 冷却 `300s` 清零。成功清零。
- 常量:`IDLE_POLL=30` `MIN_BATCH_GAP=1.5` `MAX_BACKOFF=60` `CIRCUIT_THRESHOLD=5` `CIRCUIT_COOLDOWN=300` `MODULE_TIMEOUT=300`。
- 引擎对外:`start/stop/getStats/isRunning/getModule/isBusy/updateParams`;`isBusy`=当前批在跑(供发布等批跑完再插);`updateParams` 热更参数+回复生成器。

## 5. 单视频互动流程 interactWithVideo(三模块共用)

差异仅在传入 `mp` 与可选 `matchKeywords`。顺序:

1. `shouldStop` → return。
2. **视频级(三个独立概率,互不依赖)**:`chance(videoLikeProb)`→likeVideo(likes++);`chance(videoSaveProb)`→saveVideo(saves++);`chance(videoFollowProb)`→followAuthor(follows++)。
3. **进评论区门槛**:`!interactEnable || !chance(interactProb)` → return。
4. `openComments`;`comments = listComments`。
5. **先赞后回**(顺序关键:回复弹键盘/滚面板会使点赞坐标失效):
   - **点赞**:遍历,`shouldStop || liked≥commentLikeMaxCount` break;`chance(commentLikeProb)`→likeComment(commentLikes++, liked++)、`sleep(jitter(clickWaitTime))`。
   - **回复**:遍历,`shouldStop || replied≥commentReplyMaxCount` break;`matchedKw = matchComment(c.text, keywords)`,若 `keywords 非空 && !matchedKw` → continue(配词只回命中的);`chance(commentReplyProb)`→`gen.reply({videoCaption,targetComment,author,keyword})` 生成,文本空则 break;`postReplies` 真→replyComment(commentReplies++)否则只日志预览「(回复预览·未发送)」;`replied++`、`sleep(jitter(clickWaitTime))`。
6. `finally { closeComments }`。
- 匹配词:`keywords = matchKeywords ?? params.commentMatchKeywords`(打粉可覆盖)。

**matchesPrompts(video, prompts)**(仅推荐页用):空→false;含`"*"`→true;否则 `(caption+" "+tags).toLowerCase()` 子串命中任一 prompt。`VideoInfo={caption,tags,isLive?}`。

## 6. 四模块流程

### 6.1 推荐页 runForYou(预算 randInt(5,15))
每视频:`shouldStop`/`withinWindow`/`recoverIfLost`/`detectPopup` 守卫 → `readCurrentVideo`(videosWatched++)→ **`isLive`→直接下滑不互动**;**`matchesPrompts(negPrompts)`→立即划走**;**`matchesPrompts(posPrompts)`→才 `interactWithVideo`** → `sleep(jitter(3))` 模拟观看 → `swipeToNextVideo`。**只有推荐页做 pos/neg 筛选。**

### 6.2 搜索页 runKwSearch(预算 randInt(3,8))
`keyword=pick(searchKeywords)`(空→警告 return)→ `search(keyword)` → `total=min(countSearchResults, maxResults)` → 每条:守卫 →`openSearchResult(i)`→`readCurrentVideo`(videosWatched++)→**不做提示词过滤,直接 `interactWithVideo`**→`sleep(jitter(2))`→`back`。结束 `returnToFeed`(退搜索流回推荐,否则下轮在搜索流养号)。

### 6.3 个人主页 runPersHome(每天一次触发)
`!moduleEnable`→return→`openOwnProfile`→`count=min(listOwnVideos, maxVideoCount)`→每条:守卫→`openOwnVideo(i)`→`readCurrentVideo`→`interactWithVideo`(自己作品三概率默认 0,只评论互动)→`sleep(jitter(2))`→`back`。结束 `returnFromProfile`(路径与搜索不同:底部 tab 回)。

### 6.4 关注监控/打粉 runFollowingFeed(预算 randInt(3,8))
**触发**:`following.moduleEnable`,优先级最高、与养号互斥。
1. 覆盖:`matchKeywords = following.commentMatchKeywords 非空 ? 它 : 全局`;`replyGen = following.fixedReplies 非空 ? 该话术生成器 : 全局 gen`。
2. `openFollowingFeed`(切「关注」流,点顶部关注 Tab = 注册表 `nav.following-tab`)。
3. `prevSig=""`;每条:守卫 →`readCurrentVideo`(videosWatched++)→ **到底检测**:`sig=caption+"|"+tags.join(",")`,去分隔符非空 **且** `sig===prevSig`(连续两条相同)→ break(关注流滑不动=到底;OCR 未接则 sig 空,退化为按 maxVideos)→`prevSig=sig`;`isLive`→`swipeToNextVideo`+`sleep(jitter(2))`+continue;否则 `interactWithVideo(replyGen, mp, video, matchKeywords)`→`sleep(jitter(3))`→`swipeToNextVideo`。
4. **打粉本质**:进评论区概率拉满(1)、命中词优先回复(0.8),对关注账号评论区引流。不做 pos/neg 筛选(关注的本就是目标)。结束切回推荐流(注册表 `nav.foryou-tab`)。

## 7. 评论逻辑与话术

### 7.1 匹配词 matchComment(text, keywords)
keywords 空→null(不筛选);否则 `text.toLowerCase()` 含 `k.trim().toLowerCase()` 即返回**原始该词**(作 `{kw}` 传生成器),否则 null。

### 7.2 固定话术 + 占位符(gen/fixed)
`pick(replies)` 取模板(空列表→`""`,上层不发/不预览避免空评论);展开:
| 占位符 | 展开 |
|---|---|
| `{a\|b\|c}` | 竖线随机择一(一条模板生多说法) |
| `{emoji}` | 从 `["😍","🔥","💯","👍","✨","😂","🙌","🥰"]` 随机(可多次) |
| `{user}` | 评论作者 @用户名(无则空) |
| `{kw}` | 命中词(无则空) |
最后 `\s+→" "` + trim(占位为空时清理)。

### 7.3 广告评论护栏 isAdComment(纳入回复安全)
`AD_LABEL=/(sponsored|promoted|paid partnership|赞助|推广|广告合作|品牌合作)/i`(作者或正文任意位置命中即广告);`AD_CTA=/(learn more|shop now|order now|sign up now|get offer|了解更多|立即购买|马上抢购?|立即抢购|查看详情|前往购买)/i`(**仅置顶 index≤1** 才算,防误伤)。广告条绝不点赞/回复(= 注册表 `comment.ad-first`)。

## 8. 统计口径 RunStats

## 9. 新系统落地注记(G4)

- **语义照搬、代码新写**:上述所有数值/顺序/概率是防风控资产,1:1 复刻;实现用新四层(L3 工作流调 L2 动作)。
- **参数 = ConfigPatch**:字段与 `packages/shared` 对齐,Hub 下发直接生效。
- **动作映射到 L2**:likeVideo/openComments/search/openFollowingFeed 等 = L2 动作(内部走 Step 合同 + VLM 定位),L3 只按概率决定「做不做」。
- **拟人停顿 = await 语境**:jitter 停顿保留;但「等页面加载」不再用固定 sleep,而是 `await(target,timeout)`(总纲 D4)——两者区别:**jitter 是刻意的拟人观看时长(保留),await 是等加载(替代死 sleep)**。
- **OCR 依赖**:posPrompts 精确筛选、commentMatchKeywords 匹配、关注流到底检测,都依赖 OCR 读文本(感知服务 `/ocr`);OCR 未就绪时退化(posPrompts 用 `"*"`、到底检测跳过)。
