# 坑清单 / 硬约束 checklist(G0)

autotk 2.0 **全阶段必守**的教训。全部来自旧 autotk 反复试错(`apps/mobile/CLAUDE.md` + 代码警示注释)。新系统一行代码不搬,但**这些约束是物理事实/血泪教训,漏一条大概率真机卡死**。

**读法**:每条标了「新系统在哪落地」——多数已升为总纲公理(§1)或进了 Target 注册表/L0 规格,少数是实现时的活约束。旧 `file:line` 仅作印证(根 `I:\projects\开发tk养号-发布自动化`),不是要去抄。

> ⭐ 只记 5 条的话:①`snapshotMaxDepth:1`+`waitForIdleTimeout:0`(忘了 60s 超时雪崩)②动作前 `activateApp` + session 404 要 `resetSession`(否则整夜熔断)③上划前安全闸(内嵌网页上滑=进外部页,最凶不可逆)④弯引号归一化 +「不允许」含「允许」子串(权限误点反向)⑤脱困「不盲目左滑、只告警」(乱动比卡住更糟)。

## A. WDA × TikTok 核心硬约束(违反即卡死/超时)→ 落地 L0 规格书

| # | 约束 | 后果 | 新系统落地 |
|---|---|---|---|
| A1 | 建会话后**必须** `applyFastSettings`,含 `snapshotMaxDepth:1` | 深快照 `kAXErrorIPCTimeout`(>20~60s),整个卡死 | L0 `createSession` 内联(规格书 §4);是「截图定位」方案的根本前提 |
| A2 | **不能靠元素树定位**,只能截图+图像/VLM 定位坐标 | 找按钮/读文案全失败 | 总纲公理 A1;L0 不给业务 findElements/element*(规格书 §7) |
| A3 | 触控只能用 **W3C `/actions`**(旧 `/wda/tap/0`、`touch/perform` 已移除) | 旧端点 Unhandled | L0 tap/swipe 用 `/actions`(规格书 §5) |
| A4 | 打字用 `/wda/keys` | — | L0 `typeText` |
| A5 | 建**空会话**(不传 bundleId)再 `activateApp` | 传 bundleId 等 App 启动、慢 | L0 `createSession` |
| A6 | `waitForIdleTimeout:0`、`animationCoolOffTimeout:0`、`shouldWaitForQuiescence:false` | TikTok 永不静止,不设 0 每动作等 60s | L0 `applyFastSettings`(规格书 §4) |
| A7 | 每请求 **20s 超时**(AbortController) | 否则能挂 fetch 默认 5 分钟 | L0 client 构造参数 `timeoutMs=20000` |
| A8 | **任何动作前 `activateApp(TIKTOK)`** | WDA 只作用前台,否则点到我方 App/桌面 | L2 动作开头调 `activateApp`;L0 提供原子 |
| A9 | WDA 会话设备侧失效(404)但本地 sessionId 非空 → 必须 `resetSession()` 重建 | 整夜无人值守熔断死循环、无法自愈 | L0 `resetSession`;主控健康检查触发(总纲 §7 自愈) |
| A10 | 停止后**不再把 TikTok 切前台** | 用户想停,下一动作又把 TikTok 顶上来 | 主控 `isStopping` 短路,停止后触控全 no-op |

## B. 定位/坐标的坑 → 多数因 VLM 唯一指令源而**消解**,少数仍需注意

| # | 坑(旧机制) | 新系统怎么处理 |
|---|---|---|
| B1 | 右栏图标逐视频**上下浮动 ±25px**,不能读死坐标 | **VLM 每次定位**,天然跟随浮动——旧的 `railBandCenters`+`railOffsetY` 吸附整套**不再需要**(VLM 唯一指令源的最大简化之一) |
| B2/B3 | 关注红+、评论爱心、发送键会变样/位置浮动 | 同上,VLM 每次现定位;`feed.follow` 已关注则 VLM 返回空即跳过(注册表 notes) |
| B4 | 评论面板顶端压「地点横幅」,真 ✕ 在其下 tab 栏,旧质心法会被拉偏**误进地点页** | `comments.close` 的 phrase 明确「in the comments tab bar」;VLM 定位到 tab 栏的 ✕,不再靠质心 |
| B5 | 关浮层**给了 closeAt 就别猜右上角**(右上误点触发 Shop「Pick now」) | 危险 Target 的 phrase 直指它自己的关闭钮(注册表 `ad.shop-promo` 等);不存在「猜右上角」这一步 |
| B6 | **上划前必须过安全闸**(内嵌网页上滑=进外部页) | 升为总纲:盲滑前该 Step 的 hazards 已检测(`browser.inapp` 在 globalHazards);确认无浮层才盲滑(总纲 §4 swipeNext) |
| B7 | 发布 `publish*` 锚点是占位,必须真机标定 | 改为 VLM phrase(注册表 `publish.*`),**无需标定**;G2 真机核 phrase 定位准度 |
| B8 | 搜索**点第二个结果**跳过第一个广告位 | 注册表 `search.result-2`(verified);L2 搜索动作用它 |
| B9 | anchors 单一真源、DeviceProfile 两处同步之痛 | 全 iPhone 8 一份 region 先验;**双份同步之痛结构性消失**(总纲 §12) |

## C. 弹窗/权限识别的坑 → 落地 Target 注册表 + 感知服务

| # | 坑 | 新系统落地 |
|---|---|---|
| C1 | **弯引号 U+2019 vs 直引号漏匹配**「Don't Allow」 | 注册表 `ocr` 正则用 `don.?t` 容忍直/弯/无撇号(`sys.*`);OCR 二次确认路径 |
| C2 | **「不允许」含「允许」子串**,匹配允许前先排除拒绝 | `deny/allow` 语义标签分离(注册表说明);养号流断言绝不含 allow |
| C3 | **一批绝不能点的危险按钮**(接收通知/开始创建/继续/设置触控ID/打开设置/Pick now…) | 注册表 `notes` 逐条锁死;phrase **只指向安全出口**,从不指向危险按钮 |
| C4 | 系统权限**分两路**,WDA `/alert` 读不到带地图的定位窗 | **已弃 /alert**(规格书 §7):统一截图+VLM 定位「Don't Allow」+tap,单一路径 |
| C5 | 养号期**一律拒绝权限安全**;仅发布对相机/麦克风/相册允许 | `allow` 仅 publish 页激活(注册表 activation.pageHazards.publish);养号断言无 allow |
| C6 | 内嵌网页 sheet(07)**绝不上滑**,只点左上 ✕ | 注册表 `browser.inapp` `handler:tapBox`,notes「绝不能上滑」;盲滑前必检 |
| C7 | **OCR 会拆行**(「Scroll up for fullscreen view」被拆) | 注册表 `browser.inapp` ocr 含 `full\s?screen view` 兜底;phrase 也多角度 |
| C8 | 关闭控件文字**整串精确匹配**(`^...$`)不能子串 | OCR 二次确认用整串;VLM 定位本身按语义不受此限 |
| C9 | **广告评论绝不点/回复**;CTA 词仅置顶 1~2 条算(防误伤正常评论) | 注册表 `comment.ad-first`(category/skip);L3 §7.3 isAdComment 规则;广告条爱心+评论成对丢弃保索引 |
| C10/C11 | 强/弱签名两档;忽略右侧动作栏文字 | 每个目标按 phrase 单独 grounding；弱信号靠 VLM+OCR 双确认；右栏区(x>0.85)先验排除 |

## D. 脱困/恢复纪律 → 升为总纲 onFail + 决策优先级

**核心原则:宁可停下告警,也不盲目乱动。**

| # | 纪律 | 新系统落地 |
|---|---|---|
| D1 | **不盲目自动左滑脱困**——连续 ≥2 次不在正常页只日志+告警,不触控不改 page | 总纲 §1 D6 + Step `onFail` 终点永远 `alertOperator`;绝不盲动 |
| D2 | 单次异常**先观察不返回**(横屏/图文帖偶发漏检),`lostStreak<2` 不动 | 决策函数「期望不在先当加载中轮询」(总纲 §5④);连续失败才升级 |
| D3 | 关评论**用「回到视频流」作成功标志**,不是「检测不到 ✕」;多次失败只告警不左滑 | closeComments 动作的 verify=`feed.rail`;onFail=alertOperator |
| D4 | 关评论**纯竖直下滑**(不左滑,不误触链接/商店/地点页) | closeComments 动作用竖直 swipe 手势(L2) |
| D5 | 通用模态卡视觉兜底**只在非评论页用**(评论面板结构相似会误关) | 新系统无「通用模态卡视觉兜底」(VLM 按 phrase 精确识别),此坑消解 |
| D6 | 关浮层**优先定位 ✕**,关掉了跳过后续(避免误点底层 feed) | 危险处理后 `continue` 重观测(总纲 §5①),不重复点 |
| D7 | 卡住统一 `stuckAlert` 上报管理中心,回已知页自动清 | PhoneSession.health.alert + Hub 告警;回正常页清空 |
| D8 | `backToFeedBase`:发布必须从**能看到底部 [+] 的干净基地**开始,补退 pushed 页 | publish 工作流首个动作=recoverToFeed;停止守卫防「八步空走伪报成功」 |
| D9 | 个人主页/搜索结果是 **pushed 页无底部导航**;逃离方式(左上返回/边缘手势)待真机确认 | L2 returnFromProfile/returnToFeed 动作;真机验收(G4) |

## E. 慢网络/时序 → 升为 `await` 原语,固定 sleep 淘汰

| # | 坑/规则 | 新系统落地 |
|---|---|---|
| E1 | 旧:搜索流每步固定停 2s、提交后等 10s | **`await(expected, timeout)` 轮询**替代(总纲 D4);慢网多等、快网不空耗 |
| E2 | 搜索结果上滑后等 2s 再读 | `await(search.results / feed.rail)` 替代 |
| E3 | 拟人 `jitter(2)` 步进 | **保留**(jitter 是刻意拟人观看时长,≠ 等加载;L3 §2 区分) |
| E4 | **上划要验证真划动了**(读新文案比相似度,没动就换位置重试) | swipeNext 的 verify:比 caption(OCR);盲滑后仍需验证真换了视频(总纲 §5) |
| E5 | 划动验证**依赖 OCR**,文案空/短时无法判定→退回单次上划(绝不死循环脱困) | OCR 未就绪时 verify 退化(L3 §9);绝不「永远判同一条→每次脱困」 |
| E6 | 换视频/切页后清 `railCache`+`lastCaption` | 新系统无 railCache(VLM 每次定位);PhoneSession 换视频清 history 时序缓存 |
| E7 | 清系统弹窗用**轮询**(出现就清含堆叠,连两次没有提前返回);相机+麦克风连弹两三个,循环清栈(≤4 防死循环) | 每步先做一次全屏 OCR 危险扫描；命中后单独定位安全按钮；堆叠弹窗多轮处理，同一危险 N 次关不掉→升级(总纲 §7) |
| E8 | 屏幕尺寸**只查一次**(竖屏锁定),失败用 profile 兜底 | L0/PhoneSession 缓存 windowSize;iPhone 8 固定 750×1334 |

## F. 跨项目同步纪律(接 Hub/协议时)

新系统 `services/master`/`services/perception` 进 pnpm workspace(不像旧 `apps/mobile` 被排除),**理论上可用 workspace 依赖联动**,消除旧「vendored 手动同步」之痛。但仍须守:
- **Hub 协议**:若采协议规格方案 B(聚合方/子设备),改 `packages/shared` 需同步 `services/hub` gateway。方案 A(平铺)零改动。
- **业务参数 = `ConfigPatch`**:L3 参数字段与 `packages/shared` 对齐(既有纪律,防漂移)。
- **验证**:纯逻辑(决策核/参数校验)自动化单测(mock 截图序列);L0/真机接线只能真机冒烟。
