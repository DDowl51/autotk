# autotk 2.0 协议规格

> 当前实现说明：2026-07-23。
> 跨进程边界：master ↔ perception、master ↔ Hub、master ↔ receiver。

## 1. master ↔ perception

### 1.1 传输

- HTTP
- OpenAI 兼容 `POST /v1/chat/completions`
- 图片为 PNG data URI
- 请求无服务端会话
- 服务端单 worker 串行推理
- LocateAnything 只支持 batch=1

master 使用 `@auto/perceptor-vlm` 的 `createOpenAiBackend()`。

### 1.2 请求

```jsonc
{
  "model": "locateanything-3b",
  "max_tokens": 64,
  "temperature": 0.7,
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Locate the region that matches: the like heart button. Output \"<box><x1><y1><x2><y2></box>\" with coordinates 0-1000, or \"none\"."
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/png;base64,<BASE64>"
          }
        }
      ]
    }
  ]
}
```

响应：

```jsonc
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "locateanything-3b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "<box><820><410><900><500></box>"
      },
      "finish_reason": "stop"
    }
  ]
}
```

框坐标为 0–1000，客户端归一化为 `[x1,y1,x2,y2]`。越界或退化框直接丢弃，不修补后点击。

### 1.3 单目标定位

LocateAnything-3B 一次只可靠定位一个短语：

```text
queries = [q1, q2, q3]
→ backend.infer(image, q1)
→ backend.infer(image, q2)
→ backend.infer(image, q3)
```

三次请求复用同一张调用方截图。不存在组合查询格式、请求队列 batch 或 `/perceive` 端点。

region 不写入 prompt；客户端拿到框后检查中心点是否落在 region 内。

### 1.4 OCR

OCR 复用同一个 `/v1/chat/completions` 端点，只改变指令和 token 上限：

```text
Read all visible text in the image, line by line...
<box><x1><y1><x2><y2></box> <text>
```

客户端解析为：

```ts
interface TextLine {
  text: string;
  box: [number, number, number, number];
}
```

用途：

- 评论/文案读取；
- 页级危险全屏文字预筛。

页级危险检测：

1. 一次全屏 OCR；
2. 对所有激活危险的 `ocr` 正则匹配；
3. 命中后才 grounding 定位关闭/允许/拒绝按钮；
4. 无 `ocr` 的危险才退回逐个 grounding。

直播/广告内容标记不进入页级危险。

### 1.5 健康检查

```http
GET /health
```

```json
{"ok":true,"max_side":640}
```

当前服务实现：`services/perception/server.py`。

### 1.6 错误

| 情况 | 行为 |
|---|---|
| 非 2xx | 客户端抛 `感知服务 <status>: <body>` |
| 超时 | AbortController 中止，抛含 URL/timeout 的错误 |
| 无 choices/content | 返回空文本，解析为未命中 |
| 非法框 | 丢弃为未命中 |
| OCR 异常 | 本轮页级 OCR 危险视为未命中，宁可漏检也不盲动 |

## 2. master ↔ Hub

### 2.1 方案

采用 D3 平铺：

- master 为每台手机创建一个 device socket；
- Hub 无需知道 aggregator；
- `deviceId` 使用 master 的设备 id；
- 协议单一真源为 `packages/shared/src/protocol.ts`。

### 2.2 事件

| 方向 | 事件 | 作用 |
|---|---|---|
| master → Hub | `device:register` | 注册/更新一台设备身份 |
| master → Hub | `device:status` | running/module/page/stats/alert |
| master → Hub | `device:log` | 一批 `DeviceLogMsg` |
| Hub → master | `config:apply` | 参数增量 |
| master → Hub | `config:result` | 配置应用结果 |
| Hub → master | `device:control` | pause/resume |
| Hub → master | `publish:task` | 发布任务 |
| master → Hub | `publish:result` | 下载/发布进度与终态 |

master 收到配置后：

1. 找对应 PhoneHandle；
2. 深合并参数/时段；
3. 插件重新校验；
4. 校验通过才原子替换；
5. 回 `config:result`。

### 2.3 状态

`DeviceStatus` 来自 PhoneHandle：

- `running`
- 当前 `module`
- `stats`
- `alert`
- 时间戳

当前没有可靠页面追踪与电量采集时，相应字段省略。

## 3. master ↔ receiver

内部 socket.io 协议，真源：

- `services/master/src/receiver/protocol.ts`
- vendored 副本 `apps/receiver/src/protocol.ts`

事件：

```text
receiver → master  receiver:hello
master → receiver  receiver:download
receiver → master  receiver:progress
```

消息：

```ts
interface ReceiverHello {
  udid: string; // 当前实现里必须等于 master deviceId
}

interface ReceiverDownload {
  taskId: string;
  url: string;
  videoName: string;
}

interface ReceiverProgress {
  taskId: string;
  status: "downloading" | "downloaded" | "failed";
  assetId?: string;
  error?: string;
}
```

发布时序：

1. Hub 下发 `publish:task`；
2. master 确认 receiver 在线；
3. 下发 `receiver:download`；
4. 等 `downloaded`；
5. `PhoneHandle.runExclusive("publish")`；
6. TikTok UI 发布；
7. 回 `publish:result`。

当前 receiver 的 URL/deviceId 是构建期环境变量，多机量产尚未闭环。

## 4. 兼容纪律

- 改 Hub 事件：同步 `@mc/shared`、Hub、master、desktop，并跑两端测试；
- 改 receiver 事件：同步 master 与 receiver vendored 协议，并跑两边测试；
- 改 perception 请求：以 `packages/perceptor-vlm/src/openai-backend.ts` 与 `protocol.ts` 为准，同步本规格和 server；
- 不重新引入 `/perceive`、`/ocr`、JPEG 组合查询或服务端 batch 协议。
