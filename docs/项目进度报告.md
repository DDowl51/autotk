# autotk 2.0 · 项目进度报告

> 日期:2026-07-10　状态:框架与业务逻辑(纯 TS)基本完成,进入真机联调阶段
> 一句话:已把 autotk 从「引擎跑手机、逐机标定、on-device 识别」**重构为「可复用自动化框架(core)+ 按 app 插件(TikTok)+ VLM 集中识别」**,核心逻辑全部离线 TDD 覆盖(**169 单测全绿**),剩真机/GPU 接线。

---

## 0. 摘要(TL;DR)

- **架构**:core + plugin + 依赖倒置(开闭原则)。`@auto/core` 是与 app/平台无关的引擎;TikTok 的一切在 `@auto/plugin-tiktok`;iOS 驱动、VLM 感知是可换的框架实现。以后做别的 app = 加个插件,不碰 core。
- **识别**:`LocateAnything-3B`(VLM)作坐标/决策的**唯一来源**——一句英文指令定位任意目标(点赞键/×/Don't Allow/评论头像…),替掉旧系统「逐机标定坐标 + 像素比色」两套。OCR 只读文本(评论/文案)。
- **五大功能**全部落地为工作流并端到端 mock 跑通:①关键词搜索互动 ②主页互动+私信 ③关注监控打粉 ④发布 ⑤评论区下滑。
- **测试**:`core 68 + driver 14 + perceptor-vlm 30 + plugin 57 = 169`,全部离线确定性(mock 驱动/感知/时钟),`typecheck` 干净。
- **真机工具**已备:GPU 感知服务(FastAPI 包 LocateAnything)+ 单机冒烟工具(截图→定位→点)。
- **待办**:真机验证(私信可行性、grounding 精度、组合指令格式)、`services/master` 多机装配、Postgres StateStore、Hub 对接。
- **承载量(实测下调)**:VLM 唯一指令源 = 单卡 ~10 台(裸)→ ~35–50 台(FP8+一卡多实例);几百台=多卡。

## 1. 背景与重大转向

**旧 autotk(apps/mobile)**:RN/Expo App,引擎跑在 iPhone 上,WDA 驱动 TikTok,逐机型标定坐标。痛点:iOS 后台挂起(无人值守难)、逐机标定、on-device 识别弱、代码耦合(onDeviceUI/calibratedUI 双份同步)。

**转向(需求方 2026-07-10 定案)**:
1. **推倒重来,不复用旧代码**(旧代码仅作知识库,教训已提炼进规格)。
2. **可复用框架**:以后可能做别的 app 自动化 → core+plugin+依赖倒置+开闭原则。
3. **集中式**:手机只跑 WDA(哑执行器),识别/决策集中在内网带 GPU 的主机;顺带解决 iOS 后台挂起。
4. **功能重划**:只做搜索互动 / 主页互动+私信 / 关注监控 / 发布 / 评论下滑,**砍掉推荐页养号**;新增**私信**(给主页视频评论者发私信,拉新转化)。

旧 `apps/mobile` 继续服务存量买家(OTA 修复不停),新框架平行从零长,**影子对比达标后一次性切换**。

## 2. 架构总览

### 2.1 core / plugin 分层(依赖倒置)

| 层面 | 不变 → core(框架) | 每 app 变 → plugin |
|---|---|---|
| 设备操作 | `Driver` 接口(截图/点/滑/输入) | —(iOS 都一样,driver 是平台实现) |
| 感知 | `Perceptor` 接口(grounding + OCR) | 认什么(Target 短语)= plugin 数据 |
| 控制 | Step 合同 + 观测-决策-执行-验证闭环 + await | —(算法与 app 无关) |
| 编排 | 多设备并发/调度/健康自愈/拟人化 | — |
| 业务 | — | 动作库、工作流、概率参数 |

**依赖倒置**:core 定义接口(`Driver`/`Perceptor`/`Plugin`/`StateStore`),平台/插件实现;core 不 import 任何插件。运行时装配。**开闭**:加 app=新插件不动 core;加功能=新动作模块不改老的。

### 2.2 四层操作模型
```
L3 工作流   plugin  search / profileAndDM / followMonitor / publish   (业务编排+概率)
L2 动作     plugin  interactComments / dmCommenter / scrollComments … (app 特定)
L1 基本操作 core    tapTarget/awaitTarget/find/readText/handleHazards + Step 决策
L0 原子     core接口+driver实现  tap/swipe/typeText/screenshot/activateApp
```

### 2.3 运行拓扑(目标形态)
```
┌──────────── 内网 GPU 主机 ────────────┐
│ services/master (Node)   services/perception (Python)  │
│  每台 PhoneSession + 主控循环 ──HTTP──▶ LocateAnything-3B │
│  core+driver+perceptor+plugin 装配 ◀──  (OpenAI 兼容端点)  │
│         │ 接管理中心 Hub(复用)                          │
└─────────┼──────────────────────────────────────────────┘
   │ WDA HTTP (LAN)  截图↓ 操作↑
 iPhone8 × N(只跑 WDA + TikTok 前台,零我方代码)
```

### 2.4 第一性原理(公理,一切设计的根)
- A1 屏幕即唯一真相(读不到元素树,只有截图像素)
- A2 动作是盲的(tap/swipe 无返回值,效果靠下一帧观测)
- A3 环境对抗且非确定(随时插广告/弹窗/权限窗/直播)
- A4 识别稀缺(像素≈免费、OCR 便宜、VLM 精准但贵、是吞吐瓶颈)
- A5 复用优先(跨 app 不变的能力必须与具体 app 解耦)

### 3.1 `@auto/core` 关键模块
- `interfaces.ts`:`Driver` / `Perceptor` / `StateStore` / `Hit` / `LocateQuery` / `TextLine` / `ImageBytes`。
- `target.ts`:`Target`(id/phrase/kind/hazardClass/handler/region…)+ `toRegistry`。
- `step.ts`:`Step` 合同(intent/act/expected/hazards/verify/timeout/onFail)+ `BasicOp` + `Escalation`。
- `engine.ts`:`decide`(单次闭环:危险优先→期望执行→验证轮询→超时)+ `runStep`(升级链 retry→variants→recover→**alertOperator 不盲动**,危险重跑+熔断)+ `locateTargets`;`awaitTargets` **验证等待期间也处理危险**(权限窗在页面转换时弹出会被关掉)。
- `context.ts`:`RunContext`(runStep/tapTarget/find/locate/readText/readLines/chance/jitter/sleepSeconds/state/stats…)+ `createRunContext`。
- `human.ts`:chance/jitter/randInt/pick(rng 可注入,确定性可测)。
- `schedule.ts`:分时段窗口(当天秒数判定、到下一窗)。
- `statestore.ts`:内存 StateStore(默认;生产 DM 去重/限量走 Postgres)。
- `orchestrator.ts`:`createFleet` 多机;每台主循环(时段窗→独占暂停→pickWorkflow→批次超时隔离 batchGen→退避+熔断);`runExclusive`(发布串行不抢前台);热更参数+自愈。

### 3.2 `@auto/plugin-tiktok` 关键内容
- `target-registry.json`:**62 个 Target**(声明式感知单一数据源)。危险三类:系统级(权限窗)、遮挡级(弹窗)、分类级(直播/广告评论)。含本会话真机实测的关键坐标(shop×/内嵌网页×/Don't Allow)。
- 工作流:`search` / `profileAndDM`(+私信)/ `followMonitor` / `publish` + 复用件 `scrollComments` / `interactComments` / `dmCommenter` / `interactWithVideo` / `recover` / `pick`。
- `params.ts`:`AutomationParams`(搜索/推荐/主页/关注/私信全参 + 校验 + 默认,防风控数值 1:1 复刻旧引擎)。

## 5. 关键技术决策记录

| 决策 | 内容 | 依据 |
|---|---|---|
| VLM 唯一指令源 | 坐标/决策全由 LocateAnything 出;OCR 只读文本;盲滑是唯一例外(固定手势但前置危险检测) | 需求方 + 架构简化(消灭逐机标定) |
| 弃 WDA `/alert` 通道 | 系统弹窗统一「截图→VLM 定位→tap」——带地图的定位权限窗 WDA `/alert` 读不到,tap 路径已真机实证(IMG_0008) | 单一路径 + 实证 |
| 私信限量可配 | `dmDailyCap` 默认 20/账号、可配;发不出=跳过该人(记 dm-tried) | 需求方(可设置)+ 防封 |
| 盲滑优化 | 「划下一视频」用固定手势不问 VLM(危险检测保留)→ 每台间隔拉长、承载翻倍 | 承载量(采纳) |
| region 后过滤 | 提示词保持纯 phrase(不确定模型支持区域约束);命中框中心落 region 外则丢弃 | perceptor-vlm 设计 |
| 组合指令 | 每步一次问多个目标(省 GPU),按序号解析 `<box>` | 承载量(每步 1 次 VLM) |
| **已修高危 bug** | 注册表 `region` 曾是 `[x,y,w,h]`,而 `Box` 是角点 `[x1,y1,x2,y2]` → 加载时换算(否则命中被静默过滤) | 对抗评审(d0b0330) |
| onFail 终点=告警 | 脱困升级链最后一级永远是「停手+通知管理中心」,绝不盲动(旧系统血泪:误判正常页乱左滑) | 公理 A1/D6 |

**待验证风险**(已记档):
- grounding「目标不存在时返回空」的可靠性(可能幻觉出框)→ region 后过滤 + OCR 二次确认兜底,真机验收。
- **组合多目标指令**模型服从度未验(bench 只测过单目标)→ 真机第一个要调的点(改 `protocol.ts` 一处)。
- 私信能不能发(平台隐私 + TikTok 反垃圾)→ 真机首验。

## 8. 承载量结论(2026-07-10 实测)

| 指标 | 值 |
|---|---|
| 单张 grounding 延迟(5060 Ti,768,sdpa) | ~477 ms(512:~280ms 但丢小目标 ✕) |
| 单流吞吐 | ~2.1 张/秒(**批处理不支持**,模型 only batch=1) |
| 精度 | 768 全准;弹窗×/Don't Allow 与手工量坐标吻合 ~1% |
| **单卡承载(VLM 唯一指令源)** | 裸 ~10 台 → FP8+一卡多实例 ~35–50 台 |
| 单卡承载(混合兜底) | ~38 台(裸)→ ~150–200(优化) |

**结论**:模型选型通过(精度达标);批处理不支持 → 单卡承载须靠「FP8 + 一卡多实例」逼近,**几百台=多卡分片**;非算力天花板 = WiFi(多 AP)+ WDA 长会话稳定性。详见 `LocateAnything-3B-5060Ti-性能报告.md`。

## 10. 如何运行

pnpm install
